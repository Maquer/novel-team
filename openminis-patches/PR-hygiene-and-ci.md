## PR 2：GitHub Actions CI（两层）

### 2a. lint.yml — 轻量静态检查（iSH 全量验证过，开箱即绿）
检查项：JSON/YAML/XML/plist/TOML 解析、Python `py_compile`、Shell `bash -n`、Markdown 相对链接、Swift/Kotlin 词法级括号平衡。
- 不需要 Xcode/NDK/native deps
- ~30 秒跑完
- **这条我能在 iSH 验证，敢保证可用**

### 2b. build.yml — 完整编译 CI（按 BUILDING.md 全链路，⚠️ 未验证）
按 BUILDING.md 文档顺序编排：子模块初始化 → 原生依赖构建（带缓存）→ app 编译。
- iOS job：macOS runner，brew + meson，build_lame→ffmpeg→ish→alpine_rootfs（缓存），xcodebuild
- Android job：ubuntu runner，JDK17 + NDK r28 + CMake，build_proot + prepare_android_sandbox（缓存），gradlew assembleDebug + testDebugUnitTest
- **我无法从 iSH 验证这条**（没 Xcode/AGP）。结构完整、按文档编排，但第一次跑大概率要调缓存 key / 签名 / SDK 版本。建议提 PR 时标 WIP，第一次 push 后看日志逐项修。

### ⚠️ build.yml 已知风险点（第一次跑大概率栽这里）
1. iOS 签名：`CODE_SIGNING_ALLOWED=NO` 只能验证编译链接，不能产出可安装的 ipa
2. Android NDK 版本：r28+ 具体小版本号需在 `setup-android` action 里钉死
3. 缓存 key 用 `deps/*.sh` 的 hash——如果脚本不改但 submodule 更新了，缓存会陈旧（可接受，最坏情况是重建）
4. `prepare_alpine_rootfs.sh` 下载外部 Alpine minirootfs，CI 网络可能慢/不稳
5. build_ish.sh 需要 `llvm`（编译 VDSO）+ `meson`/`ninja`，首次安装约 5-10 分钟
