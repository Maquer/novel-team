## 1. 背景与动机：为什么值得升级

v1 刚刚完成全量修复并验证通过，可以部署。但在审计和"写三章"实测中，我们亲手摸到了 **8 个结构性问题**——它们不是单个 bug，而是架构长成的样子：

| # | 问题 | 证据 |
|---|------|------|
| 1 | subprocess 编排，进程边界 bug | demo 实证：gate-check 传相对路径时，内嵌 logic-review 因子进程 cwd 不同报"文件不存在" |
| 2 | frontmatter 解析各写各的 | quality-gate.py 和 gate-check.py 各修了一次解析逻辑 |
| 3 | 阈值分裂 | wordcount-check fail 线 1350 vs gate 内部 soft_min 1500，同一"字数"两个下限 |
| 4 | stdout 混打警告行 + JSON | demo 脚本被迫用"找第一个 `{`"的脏办法解析输出；任何下游消费者都要这么干 |
| 5 | gate-check.py 上帝对象 | 9 个 `_check_*` 方法硬编码在类里，加一条检查 = 改这个文件 |
| 6 | 各工具 JSON schema 不一 | humanizer / logic-review / wordcount 输出结构各异，聚合代码全是特判 |
| 7 | fact-ledger 裸操作 JSON | 读写靠各自拼路径、拼 dict，没有访问层 |
| 8 | 无缓存 | iSH 仿真起进程贵，全书扫描会重复跑完全量检查 |

结论：v1 是"能用的脚本集合"，v2 的目标是"**可维护的写作质检框架**"。

---

## 2. 设计目标

1. 结构性消灭上表 8 类问题。
2. **保持 v1 的全部优点**：纯 Python 标准库、文件型存储、无常驻服务、单文件可独立运行可调试——这些是 OpenMinis（iOS 17 / iSH）能跑起来的根本原因，一条都不丢。
3. CLI 入口全部兼容：`tools/*.py` 的现有调用方式（参数、退出码语义）在 v2 里不断。
4. 老 case 行为一致：v2 跑 v1 的回归用例，除"已知要修的项"外，输出必须一致。

## 3. 非目标（防"第二系统效应"，先立规矩）

- ❌ 不新增检查规则（"排比三连"调优、"反乒乓链"改轮次计数是另一条线，不在本设计内）
- ❌ 不换存储引擎（不引入 SQLite/数据库；JSON 文件 + 访问层足够，且在设备上可直接打开排障）
- ❌ 不做 Web UI、不做常驻服务/守护进程
- ❌ 不改写作流程语义（P0 阻断 / P1 警告 / P2 建议的三级语义原样保留）

## 5. 接口草案

### 5.1 Chapter（`core/chapter.py`）

```python
@dataclass
class Chapter:
    path: Path            # 绝对路径（构造时即 resolve，从结构上消灭问题 #1）
    meta: dict            # frontmatter：title/author/date/word_count...
    body: str             # 正文（已剥离 frontmatter）
    novel_id: str

    @classmethod
    def load(cls, path, novel_id) -> "Chapter": ...
    def char_count(self) -> int: ...      # 唯一字数口径：全部非空白字符
    def save(self) -> None: ...
```

### 5.2 Check 插件协议（`checks/base.py`）

```python
class Severity:  # P0 阻断 / P1 警告 / P2 建议，语义与 v1 一致
    BLOCK = "P0"; WARN = "P1"; ADVICE = "P2"

@dataclass
class CheckResult:
    check: str            # 检查名，如 "ai_tone"
    status: str           # pass / fail / warning / error
    severity: str         # P0 / P1 / P2
    score: float | None   # 数值分（humanizer 加权分等），无则 None
    details: list[str]    # 人类可读明细
    suggestions: list[str]# 可执行建议
    def to_dict(self) -> dict: ...   # 固定 schema，见 §7

class Check(Protocol):
    name: str
    severity: str
    def run(self, chapter: Chapter, ctx: "Context") -> CheckResult: ...

def register(check_cls): ...   # 装饰器，注册进表
```

`Context` 携带：`config`（统一配置）、`stores`（fact/world/debt）、`novel_id`。

```python
    p0_failures: list[CheckResult]

    p2_suggestions: list[CheckResult]
    tier_1a_score: float | None
    def to_dict(self) -> dict: ...

class Orchestrator:
    def __init__(self, config, checks: list[str] | None = None): ...
    def run(self, chapter: Chapter) -> GateReport:
        # 逐个进程内调用 check；单个 check 抛异常 → 该 check 记 error，
        # 不拖死 pipeline（保留 v1 "隔离执行"的语义，去掉 subprocess 的代价）
```

### 5.4 FactStore（`stores/fact_store.py`）

```python
class FactStore:
    def __init__(self, root: Path, novel_id: str): ...
    def add(self, category, content, source, allow_test=False) -> str: ...  # 返回 F0001
    def verify(self, fact_id: str) -> None: ...
    def list(self, status: str | None = None) -> list[dict]: ...
    # ID 分配、测试源黑名单、status=unverified 默认值等 v1 已修复语义原样保留
```

### 5.5 CLI 垫片契约

`tools/gate-check.py` 等保留原有 argparse 参数，内部只做：

```python
chapter = Chapter.load(args.file, args.novel_id)
report = Orchestrator(config).run(chapter)
print(report.to_json())   # stdout 纯 JSON
sys.exit(0 if not report.will_block else 1)
```

## 6. 插件契约（新增一条检查要遵守的）

1. **注册**：`@register` 装饰器 + 在 `checks/__init__.py` import，即插即用，不改编排器。
2. **输入**：只收 `(Chapter, Context)`。需要文件 IO 走 `ctx.stores`，不自己拼路径（消灭问题 #7）。
3. **输出**：必须返回 `CheckResult`（固定 schema，`to_dict()` 可 JSON 序列化）。
4. **隔离**：`run()` 内不捕获异常——抛给编排器统一记 `error`，保证"检查没跑"永远可见（v1 修复的核心教训，不开倒车）。
5. **纯数据**：检查函数不 `print`，日志走 `core/log.py`（→ stderr）。stdout 只属于最终报告（消灭问题 #4）。
6. **severity 声明**：类属性写明 P0/P1/P2；P0 的含义是"阻断创作流程"，评审时重点看。

---

## 7. 输出契约

| 通道 | 内容 |
|------|------|
| stdout | **纯 JSON**：单个 JSON 文档，无警告行、无装饰字符 |
| stderr | 日志、警告、进度 |
| exit 0 | 通过，或仅有 P1/P2 |
| exit 1 | P0 阻断（`will_block=true`） |
| exit 2 | 运行错误（参数错误、文件不存在等） |

`CheckResult.to_dict()` / `GateReport.to_dict()` 的字段名为固定 schema，`tests/test_contract.py` 锁定。
