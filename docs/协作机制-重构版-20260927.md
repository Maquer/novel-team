## 一、为什么"日常流程"不适用AI团队

### 1.1 人类团队 vs AI团队

| 维度 | 人类团队 | AI团队 |
|------|---------|--------|
| **时间观念** | 需要上班/下班/休息 | 无时间概念，随时待命 |
| **沟通方式** | 会议、邮件、即时通讯 | 日志、文件、API调用 |
| **协作节奏** | 日循环、周循环 | 任务驱动、事件触发 |
| **状态同步** | 晨会汇报、日报 | 自动记录、按需查询 |
| **进度管理** | 打卡、考勤、工时 | 任务队列、执行日志 |

### 1.2 错误设计的问题

**原设计（已废弃）**：
```
❌ 09:00 晨会 → AI团队不需要"开会"
❌ 10:00-17:00 创作时段 → AI没有"工作时间"
❌ 18:00 日报 → AI自动记录日志，不需要"报"
❌ 周五复盘会 → AI没有"周"的概念
```

**问题根源**：
- 把人类管理习惯强加给AI
- 增加了不必要的"仪式性"操作
- 降低了协作效率（AI可以并行，人类会议必须串行）

## 二、AI团队的正确协作模式

### 2.1 核心原则

```
┌─────────────────────────────────────────────────────────────┐
│  1. 任务驱动：每个任务有明确的输入、处理、输出               │
│  2. 状态可见：通过日志和文件状态了解进度，不需要"汇报"       │
│  3. 并行处理：多个任务可同时执行，不需要排队                 │
│  4. 按需介入：用户决定何时开始、何时暂停，AI随时待命         │
│  5. 自动流转：完成一个任务后自动触发下一个，不需要"会议安排" │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 任务流模型

**传统人类团队**：
```
用户 → 分配任务 → 人类A执行 → 人类B审核 → 人类C优化 → 发布
      (串行，有等待)
```

**AI团队**：
```
用户 → 提交任务 → AI并行执行 → 自动质检 → 自动发布
      (并行，无等待)
```

**示例：创作第1章**
```
用户指令："创作第1章"
    ↓
┌─────────────────────────────────────────┐
│  同时执行：                              │
│  1. 大纲设计师 → 生成章节大纲            │
│  2. 数据分析师 → 检查历史章节一致性      │
│  3. 世界观师 → 加载世界包引用            │
└─────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────┐
│  依赖完成后执行：                         │
│  4. 主笔作者 → LLM生成初稿               │
│  5. 辅助作者 → 续写扩展                  │
└─────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────┐
│  并行质检：                              │
│  6. 审稿编辑 → 门禁检查                  │
│  7. 去AI味师 → 文风优化                  │
│  8. 数据分析师 → 字数统计                │
└─────────────────────────────────────────┘
    ↓
发布到 chapters/chapter-001.md
```

## 三、实际协作流程

### 3.1 启动项目（一次性）

```bash
# 用户指令："启动小说项目"
cd /var/minis/shared/novel-team

# AI团队自动执行：
1. 检查项目配置 → project-config.json
2. 初始化世界包 → world/world-pack.json
3. 创建大纲框架 → outline/outline.json
4. 建立角色档案 → characters/*.json
5. 设置日志系统 → logs/目录
6. 输出启动报告 → 返回给用户
```

**用户只需等待最终报告**，不需要参与中间过程。

### 3.2 创作章节（核心任务）

**用户指令**：`"创作第N章"`

**AI团队自动执行**：

#### 阶段1：准备（并行）
```bash
# 大纲设计师：读取上级大纲，生成章节大纲
python3 tools/outline-builder.py generate \
  --chapter $N \
  --input outline/vol-001.json \
  --output chapters/chapter-$N-outline.json

# 数据分析师：检查前N-1章的一致性
python3 tools/wordcount-check.py --check-history \
  --chapter $N \
  --max-deviation 0.1

# 世界观师：加载相关世界设定
python3 tools/world-init.py load-references \
  --chapter $N \
  --output world/references-$N.json
```

#### 阶段2：创作（并行）
```bash
# 主笔作者：LLM生成初稿
python3 tools/llm-integrator.py chat \
  --model glm \
  --outline chapters/chapter-$N-outline.json \
  --world world/references-$N.json \
  --output chapters/chapter-$N-draft.md

# 辅助作者：续写扩展
python3 tools/batch-replace-v2.py extend \
  --input chapters/chapter-$N-draft.md \
  --target-words 2000 \
  --output chapters/chapter-$N-expanded.md
```

#### 阶段3：质检（并行）
```bash
# 审稿编辑：门禁检查
python3 tools/gate-check.py check \
  --chapter $N \
  --file chapters/chapter-$N-expanded.md \
  --output reports/check-report-$N.json

# 去AI味师：文风优化
python3 tools/novel-humanizer.py check \
  --file chapters/chapter-$N-expanded.md \
  --fix \
  --output chapters/chapter-$N-final.md

# 数据分析师：字数统计
python3 tools/wordcount-check.py \
  chapters/chapter-$N-final.md \
  --output reports/stats-$N.json
```

#### 阶段4：归档（自动）
```bash
# 世界观师：更新事实快照
python3 tools/fact-snapshot.py write \
  --project 天命 \
  -c $N \
  --file chapters/chapter-$N-final.md

# 团队总监：记录执行日志
echo "## 章节$N创作完成" >> logs/chapter-$N.log
echo "- 开始时间：$(date)" >> logs/chapter-$N.log
echo "- 完成时间：$(date)" >> logs/chapter-$N.log
echo "- 字数：$(wc -c < chapters/chapter-$N-final.md)" >> logs/chapter-$N.log
echo "- 门禁状态：PASS" >> logs/chapter-$N.log
```

### 3.3 批量创作

**用户指令**：`"批量创作第1-10章"`

**AI团队自动执行**：
```bash
# 使用工作流模拟器批量执行
python3 tools/workflow-simulator.py batch \
  --project projects/my-novel \
  --start 1 \
  --end 10 \
  --parallel 3 \
  --output reports/batch-1-10.log
```

**系统自动**：
- 按章节顺序执行
- 每次并行处理3章
- 记录每章的执行日志
- 汇总批量执行报告

## 五、问题发现与解决

### 5.1 问题自动检测

AI团队内置问题检测机制，无需人工巡查：

| 检测项 | 触发时机 | 处理方式 |
|--------|---------|---------|
| API失败 | LLM调用时 | 自动切换到备用模型 |
| 门禁不通过 | 质检阶段 | 自动触发修复流程 |
| 事实冲突 | 事实快照写入时 | 标记警告，不阻塞创作 |
| 字数不足 | 字数检查时 | 自动触发续写 |
| AI味过高 | 去AI味检查时 | 自动触发优化 |

### 5.2 问题分级（仅影响响应速度）

| 级别 | 定义 | 响应方式 |
|------|------|---------|
| **🔴 P0** | 阻断性问题 | 立即停止，上报用户 |
| **🟡 P1** | 严重问题 | 自动降级执行，记录日志 |
| **🟠 P2** | 一般问题 | 继续执行，汇总报告 |
| **🟢 P3** | 轻微问题 | 记录日志，下次优化 |

### 5.3 用户介入时机

**用户只需在以下情况介入**：

1. **项目启动**：确认项目方向和目标
2. **重大决策**：题材变更、风格调整、目标修改
3. **质量审查**：抽查部分章节，确认质量达标
4. **问题升级**：P0级问题需要用户决策
5. **批量确认**：批量创作完成后确认是否继续

**日常执行完全自动化**，用户不需要"参与"中间过程。

## 七、最佳实践

### 7.1 用户如何高效使用AI团队

**推荐工作模式**：

```
1. 明确目标："我要创作一部100万字的玄幻小说，首发起点"
   ↓
2. 确认配置：查看 project-config.json，确认无误
   ↓
3. 启动项目：执行 team-launch.py，生成初始数据
   ↓
4. 批量创作："创作第1-10章"，系统自动执行
   ↓
5. 质量抽查：随机查看3-5章，确认质量达标
   ↓
6. 迭代优化：根据反馈调整参数，继续创作
```

### 7.2 避免的错误

❌ **不要**：
- 要求AI团队"每天早上开晨会"
- 要求AI团队"每周五写周报"
- 干预AI团队的执行细节
- 频繁修改项目配置

✅ **应该**：
- 明确目标和约束条件
- 信任AI团队的执行能力
- 抽查关键节点的质量
- 根据结果调整方向
