## 一、规范概述

为了解决各环节数据格式不统一的问题，制定本规范。所有工具的输出和输入必须遵循此规范。

---

## 二、基础类型定义

### 2.1 通用字段

所有数据对象必须包含以下通用字段：

```json
{
  "id": "string",           // 唯一标识符（UUID或时间戳）
  "type": "string",         // 对象类型
  "created_at": "ISO8601",  // 创建时间
  "updated_at": "ISO8601",  // 更新时间
  "version": "integer"      // 版本号（从1开始）
}
```

### 2.2 时间格式

- **标准格式**：`YYYY-MM-DDTHH:mm:ss.sssZ`（ISO 8601）
- **示例**：`2026-09-27T15:30:00.000Z`
- **时区**：统一使用UTC时区

### 2.3 ID生成规则（v1.1 修订，2026-09-29 C9 清账）

**两类实体采用不同 ID 语义**，按「是否有序数位置」切分：

#### A. 无内部序数的实体 → `{类型}-{YYYYMMDD}-{序列号}`
事实、角色、世界节点、道具等——创建批次即其天然身份，无内部排序含义。

```
示例：
  - fact-20260927-001（事实）
  - char-20260927-001（角色）
  - world-20260927-001（世界节点）
```

#### B. 有内部序数的实体 → `{类型}-{序数}`（不使用日期）
大纲层级（作品/卷/章节）与伏笔——序数即其在作品中的**结构位置**，不应随创建时间漂移。
日期会造成两个语义错误：① 章节编号随创建日期变动，与「第一章」的叙事含义冲突；② 同日批量创建需自维护序号，增加状态。

```
示例（outline-builder.py 实际实现）：
  - work-0001（作品，4 位序列）
  - vol-001（卷，3 位序号 = -n 参数）
  - ch-0001（章节，4 位序号 = -n 参数）
  - foil-0001（伏笔，4 位序列）
```

#### 修订原因（C9 清账，2026-09-29）
原 2.3 对大纲实体统一规定 `{类型}-{YYYYMMDD}-{序列号}`，但 `outline-builder.py` 从未实现：
- work/foreshadow 用 `work-{YYYYMMDDHHMMSS}`（时间戳，无序列号段）→ 同秒创建会碰撞
- volume/chapter 用序列式
- 即**同一工具内混用两套 ID 体系**，且两者均不符合本规范

实测另发现两处更严重的缺陷（见 TEAM.md v0.59）：重复 `-n` 创建同 ID 会**静默覆盖**既有节点；`children` 字段在 dataclass 中不存在，导致 `append` 写入一次性列表、父子层级**从未真正落盘**，`tree` 恒为空。

#### 兼容性约束
- 序数 ID 不可重用、不可覆盖：重复即报错退出（`ContractViolation` → exit 1 + `ERROR:` 前缀）
- 改 ID 格式会破坏既有数据，**不自动迁移**；历史数据按项目单独清账

## 五、数据验证规则

### 5.1 必填字段检查

每个数据模型都有必填字段，提交前必须验证：

```python
REQUIRED_FIELDS = {
    "chapter": ["id", "type", "basic_info", "content"],
    "character": ["id", "type", "basic_info"],
    "world_node": ["id", "type", "node_info"],
    "outline": ["id", "type", "structure"],
}

def validate_required(data, model_type):
    required = REQUIRED_FIELDS.get(model_type, [])
    missing = [f for f in required if not data.get(f)]
    if missing:
        raise ValidationError(f"缺少必填字段: {missing}")
```

### 5.2 类型检查

```python
TYPE_CHECKS = {
    "word_count": lambda x: isinstance(x, int) and x > 0,
    "realm": lambda x: x in REALM_LIST,
    "status": lambda x: x in ["draft", "approved", "archived"],
}

def validate_type(field, value):
    checker = TYPE_CHECKS.get(field)
    if checker and not checker(value):
        raise ValidationError(f"{field}类型检查失败: {value}")
```

### 5.3 关联检查

```python
def validate_references(data, existing_ids):
    """检查外键引用是否有效"""
    errors = []
    for key in ["volume_id", "parent_id", "target_id"]:
        ref_id = data.get(key)
        if ref_id and ref_id not in existing_ids:
            errors.append(f"引用的{key}不存在: {ref_id}")
    return errors
```

## 六、数据迁移指南

### 6.1 旧格式迁移

```python
def migrate_old_format(old_data):
    """将旧格式数据迁移到新规范"""
    # 添加必需字段
    if "timestamp" in old_data:
        old_data["created_at"] = old_data["timestamp"]
    if "ts" in old_data:
        old_data["updated_at"] = old_data["ts"]
    
    # 标准化ID格式
    old_data["id"] = format_id(old_data.get("id", ""))
    
    # 添加元数据
    old_data.setdefault("metadata", {})
    old_data["metadata"]["migrated_from"] = "v0.38.0"
    old_data["metadata"]["migration_version"] = "1.0"
    
    return old_data
```

- **向后兼容**：支持v0.38.0数据格式自动迁移
