# 写作部门优化方案 v1.0

> 设计日期：2026-09-28
> 设计者：小蒋
> 状态：待讨论验证

---

## 一、优化目标

1. **调整岗位分工**：辅助岗写全文，主笔岗校订精修
2. **融合为一个岗位**：辅助岗+主笔岗合并为「创作岗」
3. **查漏补缺**：与现有流程对比，发现冲突点
4. **双向测试**：原流程 vs 新流程，出对比报告

---

## 二、三种方案对比

### 方案A：原流程（双岗分工）

```
辅助岗（写手） → 初稿（300-500字粗稿）
     ↓
辅助岗（写手） → 扩写（1000-1500字）
     ↓
主笔岗（编辑） → 精修（2000-3000字）
     ↓
门禁检查 → 发布
```

**岗位分离**：写手负责生成，编辑负责把关
**优点**：专业分工，质量有双重保障
**缺点**：上下文切换成本高，两轮AI调用，token消耗大

---

### 方案B：新流程（双岗融合→单岗执行）

```
创作岗（融合后） → 直接写全文（2000-3000字）
     ↓
创作岗（融合后） → 自检门禁（调用所有工具）
     ↓
门禁检查 → 发布
```

**岗位融合**：写+修合一，一次生成
**优点**：上下文连贯，token节省50%+，流程简洁
**缺点**：缺少二次校验，单点故障风险

---

### 方案C：混合流程（新流程+强制质检）

```
创作岗（融合后） → 写全文（2000-3000字）
     ↓
创作岗（融合后） → 自检（四问+九维+门禁）
     ↓
主编审核 → 最终确认
     ↓
门禁检查 → 发布
```

**岗位融合+强制质检**：执行合一，质检独立
**优点**：效率+质量兼顾
**缺点**：多一个审核环节

---

## 三、与现有流程的潜在冲突

| 冲突点 | 方案A（原流程） | 方案B（融合） | 方案C（混合） |
|--------|---------------|-------------|-------------|
| 四问硬阻塞 | ✅ 每段检查 | ⚠️ 需调整为章末检查 | ✅ 每段检查 |
| 知情边界更新 | ✅ 写前更新 | ✅ 写前更新 | ✅ 写前更新 |
| 地图解锁 | ✅ 写后扫描 | ✅ 写后扫描 | ✅ 写后扫描 |
| 九维评分 | ✅ 写后检查 | ⚠️ 首次输出可能质量不稳 | ✅ 写后检查 |
| 门禁检查 | ✅ 强制 | ✅ 强制 | ✅ 强制 |
| 双备份同步 | ✅ 写后同步 | ✅ 写后同步 | ✅ 写后同步 |
| token成本 | 高（3轮调用） | 低（1轮调用） | 中（1轮+审核） |
| 质量稳定性 | 高（两轮打磨） | 中（单次生成） | 高（生成+审核） |
