## 二、各级别详细定义

### 2.1 P0级（阻断性问题）

**定义**：无法继续创作，必须立即解决

**具体场景**：
1. **API故障**
   - DeepSeek、GLM、Qwen全部调用失败
   - 所有备用模型均不可用
   - API配额耗尽且无法充值

2. **门禁全 fail**
   - 事实冲突（如主角境界前后矛盾）
   - AI味评分>30分且无法修复
   - 关键事实缺失（如角色名、地点名）

3. **数据损坏**
   - 世界包文件损坏
   - 大纲文件损坏
   - 项目配置文件丢失

**处理流程**：
```python
# 示例：P0级问题处理代码
def handle_p0_issue(issue_type: str, details: str):
    # 1. 立即暂停所有创作任务
    stop_all_tasks()
    
    # 2. 生成问题报告
    report = {
        "level": "P0",
        "type": issue_type,
        "details": details,
        "timestamp": get_current_time(),
        "impact": "阻断性，无法继续创作"
    }
    
    # 3. 30分钟内上报用户
    notify_user(report, timeout_minutes=30)
    
    # 4. 等待用户决策
    user_decision = wait_for_user_decision()
    
    # 5. 执行用户决策
    execute_decision(user_decision)
    
    # 6. 记录日志
    log_action("P0处理完成", report, user_decision)
```

### 2.2 P1级（严重问题）

**定义**：影响质量但可workaround，需尽快解决

**具体场景**：
1. **部分API限流**
   - DeepSeek限流，但GLM可用
   - 单模型失败，但有备用方案

2. **质量指标临界**
   - AI味评分15-20分（轻度超标）
   - 字数不足1500-1800字
   - 门禁检查有warning但不阻塞

3. **跨部门协作摩擦**
   - 主笔作者与辅助作者风格不一致
   - 大纲与事实快照冲突
   - 世界观师与审稿编辑标准不一

**处理流程**：
```python
# 示例：P1级问题处理代码
def handle_p1_issue(issue_type: str, details: str):
    # 1. 总监评估（15分钟内）
    assessment = director_assess(issue_type, details)
    
    # 2. 判断是否可自主解决
    if assessment["can_resolve"]:
        # 自主解决
        solution = implement_solution(assessment["solution"])
        log_action("P1自主解决", assessment, solution)
    else:
        # 需要用户决策
        report = {
            "level": "P1",
            "type": issue_type,
            "assessment": assessment,
            "recommendation": assessment["recommendation"]
        }
        notify_user(report, timeout_minutes=120)
```

### 2.3 P2级（一般问题）

**定义**：影响效率但不阻塞，可延后处理

**具体场景**：
1. **工具报错但可绕过**
   - 批量改词工具备份功能异常（可手动备份）
   - 字数统计脚本输出格式不统一（可手动修正）

2. **流程不顺但可完成**
   - 数据录入不及时（可事后补录）
   - 文件命名不规范（可整理）

3. **体验优化类问题**
   - 界面显示不美观
   - 响应速度可优化

**处理流程**：
```python
# 示例：P2级问题处理代码
def handle_p2_issue(issue_type: str, details: str):
    # 1. 记录日志
    log_issue(issue_type, details)
    
    # 2. 判断4小时内能否解决
    if can_resolve_within_hours(issue_type, 4):
        resolve_issue(issue_type, details)
        log_action("P2已解决", issue_type, details)
    else:
        # 汇总到周报
        add_to_weekly_report(issue_type, details)
```

### 2.4 P3级（轻微问题）

**定义**：建议优化类，可延后处理

   - 建议优化日报格式

2. **文档缺失**
   - 某些工具的README不完善
   - 某些流程缺少操作手册

## 三、升级机制

### 3.1 自动升级规则

| 原级别 | 超时时间 | 升级后级别 | 处理方式 |
|--------|---------|-----------|---------|
| P2 | 4小时 | P1 | 上报总监 |
| P1 | 2小时 | P0 | 上报用户 |
| P0 | 30分钟 | - | 紧急通知用户 |

### 3.2 降级规则

| 原级别 | 降级条件 | 降级后级别 |
|--------|---------|-----------|
| P0 | 用户决策后 | P1/P2 |
| P1 | 发现影响较小 | P2 |
| P2 | 发现影响轻微 | P3 |

## 五、执行示例

### 示例1：API限流（P1级）

**场景**：主笔作者创作时，DeepSeek API限流

**处理流程**：
```
1. 主笔作者发现API限流（P1级）
2. 主笔作者上报总监（5分钟内）
3. 总监评估：DeepSeek限流，但GLM可用
4. 总监自主决策：切换到GLM模型
5. 记录日志："2026-09-27 15:30 DeepSeek限流，已切换到GLM"
6. 通知主笔作者："已切换模型，继续创作"
```

### 示例2：事实冲突（P0级）

**场景**：审稿编辑发现第5章与第10章主角境界不一致

**处理流程**：
```
1. 审稿编辑发现冲突（P0级）
2. 审稿编辑上报总监（5分钟内）
3. 总监评估：属于严重事实冲突，影响故事逻辑
```

## 七、常见问题FAQ

**Q1：如何判断问题是P0还是P1？**
A：看是否阻断创作。如果无法继续创作，是P0；如果能workaround但影响质量，是P1。

**Q2：P1级问题什么情况下需要上报用户？**
A：当总监评估后认为需要用户决策时（如涉及重大创作方向调整、成本超支等）。

**Q3：P2级问题4小时内未解决怎么办？**
A：自动升级为P1级，按P1流程处理。

**Q4：可以同时存在多个P0级问题吗？**
A：可以，每个P0级问题都需要独立处理，按紧急程度排序。

**Q5：用户24小时内未回复P0级问题怎么办？**
A：持续尝试联系用户（每2小时一次），同时准备降级方案（如切换到mock模式）。
