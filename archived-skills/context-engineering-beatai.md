# 上下文工程：悄然取代 Prompt 工程的学科
> 来源：BeatAI (beatai.org) | 作者：Shrashti Singhal | 日期：2026-08-20
> 原文链接：https://beatai.org/ai-insights/context-engineering-the-discipline-that-quietly-replaced-prompt-engineering
> 原始发布：pub.towardsai.net

## 简介
Agentic AI 时代的核心技能从 prompt 工程转向上下文工程——不是优化一句话，而是策划模型每次调用能看到的全部内容。

## 核心内容

### 上下文窗口结构（典型 agent）
- 系统 prompt：~3%
- 工具定义：变化
- 消息历史：中等
- **工具结果：70%+**

手写 prompt 通常是最不重要的部分。

### 两个隐藏问题
1. **中间迷失**：模型关注首尾，中间信息被忽略
2. **上下文腐化**：填充后性能下降，模式匹配替代推理

### 四维故障分类
| 类型 | 描述 | 例子 |
|------|------|------|
| 污染 | 幻觉进入上下文后被当真理 | 步骤12虚构文件名→步骤13-40基于它 |
| 干扰 | 累积内容淹没指令 | 90分钟后 agent 违反初始约束 |
| 混淆 | 无关信息影响输出 | 40个工具定义只用了3个 |
| 冲突 | 矛盾信息无原则性解决 | 旧需求 vs 新需求 |

### KV Cache 经济铁律
- 缓存命中 ≈ 新 token 成本 1/10
- **前缀稳定优先级最高**：时间戳等单 token 变化可使账单翻 10 倍
- 只追加不编辑历史记录
- 会话中不增删工具（需限制时屏蔽而非删除）

### 六技工具箱
1. **严格筛选**：工具结果返回最小必要内容
2. **压缩**：70-85% 阈值触发，保留决策+约束+精确标识符，丢弃死胡同
3. **外部存储器**：plan.md/notes.md，文件系统 > 窗口记忆
4. **背诵**：最近输出末尾重述作业清单，操纵注意力曲线
5. **即时检索**：grep/glob 按需拉取，渐进式披露而非预装
6. **隔离**：子 agent 做上下文防火墙

### 反直觉规则
失败记录不要洗白。能看失败的模型会避免重复错误；抹去证据 = 恶性循环。压缩时保留"尝试 X → 失败，因为 Y"。

### 案例
- **Claude Code**：信念驱动精简（glob/grep JIT + CLAUDE.md + 手动/自动 compact）
- **Manus**：KV Cache 学派（稳定前缀 + 文件系统 + 可恢复压缩）
- **百万 token 窗口**：海市蜃楼，长窗口 ≠ 无需策划

## 关键金句
- "模型没变笨，只是快淹死了"
- "你允许的每个 token 都在与其他所有 token 竞争"
- "更大的窗口只是更大的画布，内容策划能力才决定飞多接近上限"
- "prompt 工程问'我该怎么措辞'；上下文工程问'我能展示的所有信息里，哪些最值得展示'"

## 与我体系的映射
- 四维故障分类 → skill-eval-gate.py 诊断框架
- 压缩策略（保留决策+标识符 vs 丢弃死胡同）→ 对齐 obsidian-distill.py
- 前缀稳定性经济账 → GLOBAL.md §四 需补充
- 自动压缩机制 → minis-cli 应加 compact 命令

## 局限
- 主要面向编码 agent（Claude Code/Manus），内容创作场景适配度待验证
- 未讨论视觉/多模态 agent 的上下文管理差异
