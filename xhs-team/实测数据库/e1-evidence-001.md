## 六、关键发现(给昭断的写作素材)

### 发现 1:2B 小模型暴露推理过程 = 直接不可用
MiniCPM5-2B 的 API 输出包含 chain-of-thought 推理过程(如"用户是商家,语气要活泼""我需要先确定文章结构"),用户看到的是模型思考过程而非成品。这是 API 调用的典型问题——网页版通常隐藏推理,但 API 原样输出。**对写作场景直接不可用**。

### 发现 2:4 款中 3 款水平接近,差异不在"会不会"而在"什么风格"
- **Qwen**:文艺范,像"有生活感悟的文艺青年"(有朋友真实案例,语言有质感)
- **MiMo**:活泼范,像"会玩梗的年轻职场人"(用"卷王""开车党狂喜"等网络用语)
- **DeepSeek**:稳重范,逻辑推理最清晰,但文风偏"正式报告"

### 发现 3:润色任务(D)是全模型短板
4 款模型在 D 任务(27-34 字)上实用性均 ≤ 3 分——润色过度简化,信息量损失大。这是通用语言模型的共性问题:对"保留原意"的约束执行不好。

### 发现 4:逻辑推理(C)是区分度最大的维度
DeepSeek/Qwen/MiMo 全部正确(乙说真话),但 MiMo 的穷举验证最完整(三种假设逐一验证)。MiniCPM 推理过程被截断,无明确结论。
