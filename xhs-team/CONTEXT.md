## 关键决策

| 决策 | 内容 | 理由 |
|------|------|------|
| 平台 | 单平台小红书起步 | 唯一有 API 通路；其他平台无自动化能力 |
| 团队独立 | 与公众号完全隔离 | 门禁体系不同、数据建模不同、失败形态不同 |
| 明镜归属 | 跨线共享岗 | 公众号需真实截图，小红书需实物实拍 |
| 岗位数 | 9 人 | 用户确认接受 |
| 命名方案 | 秉裁/考实/履验/昭断/明镜/端绳/探津/慎堤/司准 | 用户确认 |

## 门禁体系（E1-E4）

| 门禁 | 名称 | 判定 | 不通过处理 |
|------|------|------|-----------|
| **E1** | 实测证据表 | 每个缺点结论必须有测试条件 + 数据 + 复现步骤 | 退回履验补测 |
| **E2** | 主客观分离 | 「我觉得」与「它发热」不得混写 | 强制拆分标注 |
| **E3** | 利益披露 | 送测/自购/品牌合作必须首图或前三行显著标注 | **不发，无例外** |
| **E4** | 无信息量贬损 | 「设计脑残」类不可验证表述 | 退回改为可验证陈述 |

> **送测机特别规则（秉裁独占裁决）**：写不写缺点由秉裁裁，裁定结果记入危机案例库。证据强度提高一档（样本≥3 + 实拍图佐证）。

## 反自欺表（核心信条）

| 自我开脱 | 真相 |
|---------|------|
| "这产品太热门，不写缺点没人信" | 写不写缺点由证据决定，不由流量决定 |
| "送测的写两句不痛不痒的缺点就行" | 不痛不痒的缺点 + 未披露送测 = 信誉归零 |
| "标题写得夸张点没事，反正内容实在" | 本线读者从搜索进来，标题党直接差评+举报 |
| "参数抄官网的，比实测快得多" | 抄来的缺点评价读者能看出来，且法律上站不住 |
| "数据差一点没关系，先发出去" | 样本不足就发，等于把结论建立在噪音上 |
| "评论区骂两句删了就好" | 不截图取证，事后无法证明说过什么 |
