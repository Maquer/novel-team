# 小红书评测团队 · 职责手册

> v1.0 | 2026-09-23
> 适用：小红书图文评测笔记端到端生产（选品 → 实测 → 成稿 → ≥图 → 发布 → 舆情）
> 与公众号线（gzh-team）**物理隔离**：门禁体系不同、数据建模不同、失败形态不同

## 0. 为什么必须独立成线（不是给公众号加个模式）

| 维度 | 公众号线 | 本线 |
|------|---------|------|
| 流量来源 |推荐阅读 + 标题吸引 | **搜索关键词匹配** |
| 信息载体 | 文字为主，图辅助 | **图承载结论，文字补充** |
| 篇幅 | 800–1200 字 | **≤1000 字（含空格符号标点）** |
| 素材标准 | 关键事实 ≥2 独立来源（二手交叉） | **缺点结论必须一手实测，二手禁入缺点** |
| 核心风险 | 事实错误 → 更正道歉 | **商业诋毁 → 平台主动删 + 律师函** |
| 失败形态 | 阅读量低 | **删稿 / 限流 / 公开冲突** |
| 门禁体系 | G1–G13 | **E1–E5** |
| 数据 | 公众号后台留言数 | **独立建模，不混算** |

> **最后两行是隔离的根本理由**：公众号试错失败只是没人看；本线失败会引发公开冲突并被平台处罚。同一套门禁不可能同时适配这两类风险。

## 2. 生产流水线

```
01秉裁 定选品（含机器来源判定）
    ↓
02考实 竞品池 + 参数核对 + 背景素材
    ↓
03履验 一手实测 → 写入 实测数据库/（必要条件+数据+复现步骤）
    ↓
05明镜 ⇄ 04昭断  图文协同（图单 → 拍摄 → 验证 → 成稿）
    ↓
07探津 关键词与标题布局（搜索词前置，非爆款腔）
    ↓
06端绳 E1–E4 门禁（E3 不过 = 不发）
    ↓
发布（xiaohongshu-hub API ／ 手动）
    ↓
08慎堤 舆情监控 → 评论分级处置
    ↓
09司准 数据回收 → 下一篇判断
```

**硬性前置**：履验未完成，昭断不得动笔。⛔ **硬耦合** — 顺序不可调换。理由——边写边补测会导致结论先行、数据凑数。

## 3. E1–E6 评测专属门禁（端绳独占执行权）

> 与公众号 G1–G13 **不同编号、不同判据、不可互替**。G 系列管"写得对不对"，E 系列管"说这话会不会被追责"。

| 门禁 | 判定标准 | 不通过处理 | 性质 |
|------|---------|-----------|------|
| **E1 实测证据** | 每个缺点结论 → 测试条件 + 数据 + 复现步骤，缺一即挂 | 退回履验补测；无法补测则改写为「未实测，据公开资料」 | 硬阻断 |
| **E2 主客观分离** | 「我觉得」与「它发热」不得混写在同一句 | 强制拆分标注；主观判断须标「个人体验，仅供参考」 | 硬阻断 |
| **E3 利益披露** | 自费 / 送测 / 品牌合作 → 首图或正文前三行显著标注 | **不发。无例外，无"这次特殊"** | 硬阻断 |
| **E4 无信息量贬损** | 「设计脑残」「割韭菜」类不可验证表述 | 退回，改为可验证陈述（差在哪个具体动作）| 硬阻断 |
| **E5 AI 虚假人设/经历** | 第一人称叙述中的个人经历/体验是否可验证（时间/地点/对象/场景）；【个人体验】标签不能豁免 E5 | 退回昭断改写（删第一人称或补充可验证细节）；无法验证则改为客观陈述 | 非硬阻断（端绳给 FAIL 清单，昭断自行决定如何改） |
| **E6 导流合规** | 标题/正文/评论是否有联系方式引导；是否含"地球号""薇""加我"等暗号词；是否高频引导去其他平台 | 🔴 硬阻断（联系方式/暗号词）；🟡 软警告（高频站外引导 ≥3处） | 硬阻断 |

### E5 详细规则（2026-09-24 新增，端绳提案 + 秉裁裁定）

**判断原则**：
- 「个人体验」标注只是声明主观，不是豁免牌——E5 要求第一人称叙述中的**经历**可被外部验证
- 可验证 = 有具体时间 / 地点 / 对象 / 场景，读者能复现或复核
- 不可验证 = 纯观点句（"选谁看调性"）/ 无场景描述（"直接关窗"）/ 无对象（"用户是商家"未指明是谁说的）

**常见 FAIL 形态**：
1. 无场景的行为描述：「拿到 X，直接关窗」→ 缺客户端名 / 时间 / 任务场景
2. 纯观点句：「选谁看账号调性」→ 无评分依据 / 无样本支撑
3. 第一人称感受无证据：「我觉得很卡」→ 应改为「C 任务输出耗时 >10s，实用性 2 分」

**处理边界**：
- E5 FAIL ≠ 硬阻断（区别于 E3）
- 端绳给 FAIL 清单 + 修改方向，不代昭断改稿
- 修改完成后复审，E5 转 PASS 即放行，无需秉裁介入

### E1 实测证据表格式（履验交付物，端绳验收依据）

| 结论 | 测试条件 | 数据 | 复现步骤 | 样本数 |
|------|---------|------|---------|--------|
| 例：高负载 20 分钟后背部 43.2℃ | 室温 26℃／原神最高画质／亮度 80%／飞行模式 | 25℃→43.2℃ | 见 实测数据库/xxx.md | 3 次取中位数 |

> **基准方法（写死，防自欺）**：每组跑 4 次**丢弃第一次**（预热文件/设备缓存，否则先跑的吃亏），后 3 次取**中位数**（单次噪音大）。
> **数据可信度自查**：数值过于整齐（全是 100 的倍数）反而可疑——真实测量应该是有零头的。

### 送测机特别规则（秉裁独占裁决）


送测机写缺点是本线**最高风险动作**。三条硬规定：

1. **送测事实必须披露**（E3），不可用"自购"表述掩盖
2. **写不写缺点由秉裁裁定**，昭断与端绳均无权单独决定；秉裁裁定结果与理由记入 `危机案例库/`
3. **裁定为"写"时，证据强度门槛提高一档**：E1 样本数 ≥3 且必须附实拍图佐证（明镜确认非 AI）

> 理由：送测写缺点被厂商追责时，唯一站得住的是"数据可复现 + 已披露利益关系"。二者缺一，团队没有申辩余地。

## 5. 反自欺表（全团队共性）

| 自我开脱 | 真相 |
|---------|------|
| "这产品太热门，不写缺点没人信" | 写不写缺点由证据决定，不由流量决定 |
| "送测的写两句不痛不痒的缺点就行" | 不痛不痒的缺点 + 未披露送测 = 一旦被扒，信誉归零 |
| "标题写得夸张点没事，反正内容实在" | 本线读者从搜索进来，标题党直接差评+举报 |
| "参数抄官网的，比实测快得多" | 抄来的缺点评价读者能看出来，且法律上站不住 |
| "数据差一点没关系，先发出去" | 样本不足就发，等于把结论建立在噪音上 |
| "评论区骂两句删了就好" | 不截图取证，事后无法证明说过什么 |
