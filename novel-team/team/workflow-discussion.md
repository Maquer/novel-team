# 团队内部工作流程讨论报告

> 讨论时间：2026-09-27
> 参与成员：8人
> 讨论主题：内部工作流程优化

---

## 一、讨论背景

为优化小说团队内部工作流程，提升创作效率和质量，特组织本次团队内部讨论。各成员基于岗位职责，对现有流程进行审视，提出改进建议。

---

## 二、各环节问题与改进建议

### 2.1 大纲设计环节（大纲设计师发言）

**当前流程**：
```
大纲设计师 → outline-builder → add-chapter → 主笔作者
```

**发现问题**：
1. **章节粒度问题**：目前大纲只到"章"级别，但实际创作需要"场景"级别
2. **伏笔管理滞后**：伏笔埋设和回收没有时间线规划，容易遗漏
3. **大纲与事实不同步**：大纲变更后，事实快照未及时更新

**改进建议**：
- 建议增加"场景"级别的大细粒度（章→场景→段落）
- 建立伏笔时间线，明确埋设章节和预期回收章节
- 大纲变更时自动触发事实快照更新

**责任成员**：大纲设计师、世界观师

---

### 2.2 LLM创作环节（主笔作者发言）

**当前流程**：
```
主笔作者 → llm-integrator → chat → plot-analyzer
```

**发现问题**：
1. **API调用成本高**：每次创作都调用完整API，未做缓存优化
2. **上下文管理不完善**：RTCO框架未完全落地，多轮对话历史丢失
3. **模型选择单一**：只用glm一个模型，未发挥多模型对比优势
4. **重试机制缺失**：API失败时无自动重试，导致创作中断

**改进建议**：
- 实现API调用缓存，相似prompt复用结果
- 完善RTCO框架，保存对话历史到fact-ledger
- 引入多模型对比，根据章节类型选择最优模型
- 增加重试机制（最多3次，间隔递增）

**责任成员**：主笔作者、团队总监

---

### 2.3 批量处理环节（辅助作者发言）

**当前流程**：
```
辅助作者 → batch-replace → replace → 审稿编辑
```

**发现问题**：
1. **替换规则不明确**：batch-replace缺乏规则定义，容易误改
2. **备份机制缺失**：批量修改前未自动备份，风险高
3. **预览功能不足**：缺少修改前后对比预览
4. **与大纲脱节**：批量修改后未同步更新大纲

**改进建议**：
- 建立替换规则库，明确可替换词表
- 批量操作前强制备份，备份文件带时间戳
- 增加预览模式，显示修改前后对比
- 修改后自动触发大纲更新检查

**责任成员**：辅助作者、审稿编辑

---

### 2.4 门禁检查环节（审稿编辑发言）

**当前流程**：
```
审稿编辑 → gate-check → check → 去AI味师
```

**发现问题**：
1. **门禁规则僵化**：6道门禁全部通过才能进入下一环节，缺乏柔性
2. **检查结果不透明**：仅返回pass/fail，无具体错误位置
3. **未与其他系统联动**：门禁结果未同步到fact-ledger
4. **缺乏学习机制**：常见错误未积累，重复犯错

**改进建议**：
- 引入分级门禁（P0阻断/P1警告/P2建议），P0阻断其他可继续
- 输出详细检查报告，标注错误位置和修改建议
- 门禁结果自动写入fact-ledger，建立检查档案
- 积累常见错误模式，建立错误库供参考

**责任成员**：审稿编辑、去AI味师

---

### 2.5 去AI味优化环节（去AI味师发言）

**当前流程**：
```
去AI味师 → novel-humanizer → check → fusion-engine → fuse
```

**发现问题**：
1. **检测标准不一致**：Tier 1A/1B分类有时模糊，判断主观
2. **修复过度**：为降低AI味而破坏原文风格和语义
3. **指纹蒸馏质量参差**：5源文选取不当会导致风格失真
4. **与创作脱节**：去AI味后的文本与大纲情节可能不一致

**改进建议**：
- 明确Tier 1A/1B判定标准，建立判定 checklist
- 设置修复上限（每章最多修改3处），避免过度优化
- 指纹蒸馏前进行质量评估，源文不符合要求则拒绝
- 去AI味后重新检查情节一致性

**责任成员**：去AI味师、主笔作者

---

### 2.6 事实管理环节（世界观师发言）

**当前流程**：
```
世界观师 → fact-snapshot → write → 大纲设计师
```

**发现问题**：
1. **快照粒度太粗**：目前按章节存储，缺少场景级快照
2. **冲突检测滞后**：只在写入时检查，未做预检
3. **历史版本缺失**：事实变更无版本控制，无法回滚
4. **与世界包脱节**：fact-snapshot和world-pack数据未同步

**改进建议**：
- 增加场景级快照，支持细粒度追踪
- 写入前进行冲突预检，提前发现矛盾
- 建立事实版本控制，每次变更生成新版本
- 世界包变更时自动同步到fact-snapshot

**责任成员**：世界观师、大纲设计师

---

### 2.7 合同校验环节（团队总监发言）

**当前流程**：
```
团队总监 → contract-tree → check → 完成
```

**发现问题**：
1. **校验范围有限**：只检查账目咬合，未覆盖剧情逻辑
2. **人工介入少**：总监审核流于形式，未深度参与
3. **与创作脱节**：合同树更新不及时，与实际进度不符
4. **缺乏预警机制**：发现问题后无自动通知

**改进建议**：
- 扩展校验范围，增加剧情逻辑一致性检查
- 总监定期（每周）深度审核关键节点
- 合同树与实际进度自动同步
- 发现问题自动通知相关责任人

**责任成员**：团队总监、各角色

---

## 三、跨环节协作问题

### 3.1 信息传递问题

**问题**：各环节输出格式不统一，信息传递存在损耗

**建议**：
- 制定统一的数据交换格式（JSON Schema）
- 建立环节间自动数据转换机制
- 关键环节增加人工确认节点

### 3.2 进度同步问题

**问题**：各环节进度不同步，存在等待和空转

**建议**：
- 建立实时进度看板（dashboard）
- 设置环节间依赖关系，自动触发下一环节
- 异常情况自动上报总监协调

### 3.3 质量反馈问题

**问题**：质量问题发现滞后，修复成本高

**建议**：
- 建立质量追溯机制，记录每个问题的发现和修复过程
- 设置质量里程碑，定期检查整体质量
- 质量问题复盘，避免重复犯错

## 四、流程优化方案

### 4.1 短期优化（1周内）

1. **统一数据格式**
   - 制定JSON Schema规范
   - 各环节按规范输出

2. **增加备份机制**
   - 批量操作前自动备份
   - 关键节点保存快照

3. **建立基础监控**
   - 各环节耗时统计
   - 异常自动告警

### 4.2 中期优化（2-4周）

1. **引入柔性门禁**
   - P0/P1/P2分级处理
   - 允许部分问题带病运行

2. **完善事实管理**
   - 增加版本控制
   - 实现冲突预检

3. **建立知识沉淀**
   - 积累常见问题库
   - 建立最佳实践文档

### 4.3 长期优化（1-3月）

1. **智能化升级**
   - 引入AI辅助决策
   - 自动推荐优化方案

2. **协作机制完善**
   - 建立每日站会机制
   - 完善跨部门协作流程

3. **质量体系建设**
   - 建立质量指标体系
   - 实施全面质量管理

## 六、讨论结论

### 6.1 核心共识

1. **流程需要柔化**：过于刚性的流程会降低效率，需要分级处理
2. **数据需要统一**：各环节数据格式不统一是最大痛点
3. **反馈需要及时**：问题发现越晚，修复成本越高
4. **协作需要机制**：建立定期沟通和同步机制

### 6.2 立即行动

1. 制定统一数据格式规范
2. 为关键工具增加备份功能
3. 建立每日站会制度
4. 启动柔性门禁改造

### 6.3 后续跟进

1. 每周进度汇报
2. 每月流程复盘
3. 每季度全面优化
