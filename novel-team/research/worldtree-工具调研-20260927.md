## 一、工具概述

### 1.1 基本信息

| 项目 | 内容 |
|------|------|
| 名称 | worldtree（世界树）|
| 定位 | 自设世界观框架 + 生成器 |
| 技术栈 | 纯前端 HTML+JS，零依赖 |
| Stars | 0 ⭐ |
| 特性 | 离线可跑、文件夹即真相源 |

### 1.2 核心特色

1. **设定即数据**：每条设定 = Markdown 文件，可 diff、可质疑、可追溯
2. **一致性检查**：21条确定性规则，可进 CI
3. **生成流水线**：从种子生成完整世界（神话→地理→民族→王朝→历史）
4. **双向产品**：工作台（管理已写世界）+ 工厂（从零生成世界草稿）

## 二、核心概念

### 2.1 世界包（World Pack）

```
霜关纪/
├── world.md                    # 世界元信息
├── lore/
│   ├── 01-法则/誓言必偿-e7f3.md
│   ├── 03-纪元/第一纪-a1b2.md
│   ├── 04-地点/霜关-c3d4.md
│   ├── 08-人物/沈夜舟-e5f6.md
│   └── 10-事件/霜关之变-a7b8.md
├── sources/卷一原始设定稿-s1a2.md  # 出处
├── notes.json                  # 批注
└── issues.json                 # 体检结果
```

**关键设计**：
- `id` 是唯一连接点
- 名字、别名、正文随便改，别改 id
- `to` 可以先写名字，等建好边自动落地
- 正文里的 `[[链接]]` 是一等公民

### 2.2 条目类型（23种，6组）

| 组 | 类型 |
|---|---|
| 根 · 不可选择的前提 | world, law, myth, power, secret |
| 干 · 舞台 | era, realm, region, place |
| 枝 · 长时段 | race, culture, lang, term, faith, god |
| 梢 · 中时段 | org, dynasty, figure, thing, work |
| 叶 · 作为 | event |
| 芽 · 未写 | story, note |

### 2.3 关系类型（30种）

- 层级：位于/隶属/部分/分支
- 血缘：父母/配偶/兄弟/祖先/继承人
- 社会：领袖/盟友/敌对/臣属/效力/爱慕/背叛/亏欠/信奉
- 所属：持有/被造/材质
- 因果时序：导致/早于/发生于期间/参与
- 语义：提及/译作/同一事物/与…矛盾/约束

### 2.4 状态（5种）

| 状态 | 含义 |
|------|------|
| canon | 正典（你亲自确认的）|
| draft | 草稿（还没定）|
| disputed | 存疑（故意保留的矛盾）|
| retired | 已废（旧设定）|
| extracted | 待确认（AI草稿）|

## 三、一致性检查（Linter）

### 3.1 设计原则

- **只用规则，不用模型**：同样输入必给同样结果
- **每条问题带指纹**："已解决"状态能跨扫描保留
- **severity 三级**：error / warning / info

### 3.2 规则清单（21条）

| 级别 | 规则 | 说明 |
|------|------|------|
| error | dangling_relation | 关系指向不存在的条目 |
| error | broken_link | 正文链接落空 |
| error | causal_cycle | 因果成环 |
| error | post_death_action | 死亡之后还在行动 |
| warning | duplicate_entity | 疑似重复条目 |
| warning | alias_conflict | 别名指向两条条目 |
| warning | rel_domain_mismatch | 关系两端类型不匹配 |
| warning | rel_date_invert | 关系起止时间倒置 |
| warning | orphan | 孤岛条目 |
| warning | empty_stub | 空壳条目 |
| warning | canon_no_source | 正典却没有出处 |
| warning | ai_unconfirmed | AI抽取未经确认 |
| warning | era_overlap | 纪元区间重叠 |
| warning | term_drift | 译名漂移 |
| info | event_no_actor | 事件没有人参与 |
| info | out_of_era | 落在所有纪元之外 |
| info | folder_unknown | 文件夹不存在 |
| info | source_unused | 来源没人引用 |
| info | law_unbound | 法则没有约束对象 |

### 3.3 特殊设计

- **引文核验**：AI给的quote必须在来源原文里逐字出现
- **死后行动**：只有事件文本点名了某个实体才算它死了

## 四、生成流水线（工厂）

```
seed + params
  ├─ lexicon.js    语族模板 → 音素→汉字映射
  ├─ cosmogony.js  创世母题、界域、神系
  ├─ geography.js  Simplex高程 → 温度/湿度/洋陆 → 群系 → 河流
  ├─ civ.js        故土分配 → 文化/语言/宗教 → 政体 → 王朝
  ├─ sim.js        每纪10阶段推演（生长/接触/战争/信仰/...）
  ├─ narrate.js    事件 → 编年体/传奇体/考据体
  ├─ tree.js       世界树 + 径向布局
  └─ packout.js    ★ 固化桥：世界 → 世界包
```

## 七、关键发现

### 7.1 "设定即数据"的理念

worldtree最核心的创新是：**把设定当成数据来管理**，而不是散文式的描述。

这带来了几个关键优势：
1. **可diff**：Git可以追踪每次改动
2. **可质疑**：每条设定都可以被挑战
3. **可追溯**：每条设定都有出处
4. **可一致性检查**：结构化数据可以做自动化验证

### 7.2 确定性检查的价值

> "只用规则，不用模型：同样输入必给同样结果，能进 CI"

这与我们的"程序做程序能做好的事，模型做模型擅长的事"理念完全一致。

### 7.3 工厂的定位

worldtree把工厂定位为"你从零开始卡住时，让它先长出一整个世界，然后你进去改、删、质疑"。

这个定位非常精准：工厂不是主角，真正的设计从你改动第一条设定开始。
