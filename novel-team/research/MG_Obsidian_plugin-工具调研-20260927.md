## 三、核心功能详解

### 3.1 Folder to TXT（合并导出）

```
文件夹/
├── 第001章.md
├── 第002章.md
└── 第003章.md

↓ 合并后

第001章 惊变
（正文……）

第002章 入局
（正文……）
```

**关键设计**：
- 按文件名排序（建议用`第001章`前导零）
- 跳过YAML frontmatter
- 自动补章节标题

### 3.2 文件夹查找替换（批量改词）

**两个入口**：
- 长按单文件 → 「在此笔记中替换…」
- 长按文件夹 → 「在此文件夹中替换…（223）」← 显示文件数

**关键设计**：
- 跳过YAML默认开启（只改正文不改元数据）
- 备份默认开启（原件安全）
- 先预览再替换（避免误操作）
- 全字匹配对中文无效（按普通查找走）

### 3.3 AI写作助手

**三个用法**：
1. 选中文字 → AI处理（11种内置动作）
2. AI续写当前笔记（取前3000字背景）
3. 侧边栏聊天

**内置动作**：
续写 / 扩写 / 润色 / 精简 / 增强描写 / 优化对话 / 纠错 / 换说法 / 起标题 / 总结 / 提取设定

**自由指令**：
弹窗底部可写「把这段改得更压抑一点」

### 3.4 MultiTTS Reader（朗读）

**悬浮条设计**：
```
[▶] [⏸] [■]   7/100
```

**从光标处开始**：
- 光标在开头 → 读全文
- 光标在中间 → 从光标往后读
- 光标在末尾 → 提示「没有内容了」

## 五、关键发现

### 5.1 移动端创作的痛点

MG_Obsidian_plugin解决了移动端小说创作的几个核心痛点：
1. **批量操作**：手机上改人名太麻烦，这个插件解决了
2. **导出困难**：手机端导出成书不方便，Folder to TXT解决了
3. **朗读需求**：写累了听书，MultiTTS Reader解决了

### 5.2 模块化设计的价值

每个插件独立可用，Core只做依赖管理：
- 用户可按需安装
- 冲突检查自动提醒
- 状态一目了然

### 5.3 安全设计

- 备份默认开启
- 先预览再替换
- 二次确认机制

这些都是防止误操作的重要设计。
