## 三、核心功能

### 3.1 新手三命令

| 命令 | 功能 | 执行内容 |
|------|------|---------|
| `/一键开书` | 自动完成开书全流程 | 引导确认五要素→创建项目结构→生成主线计划→建立知识库→构建检索索引 |
| `/继续写` | 日常推进章节 | 续写前引导→RAG检索→大纲锚点检查→Beat Sheet生成→章节合成→门禁校验→索引更新 |
| `/修复本章` | 门禁失败后修复 | 分析失败原因→生成最短修复路径→重新执行门禁 |

### 3.2 强制章节闭环（五步门禁）

```
/更新记忆 → /检查一致性 → /风格校准 → /校稿 → /门禁检查
    ↓           ↓            ↓           ↓           ↓
 同步状态    冲突检测     文风校准   去AI味    gate_result.json
```

**任何一步未通过，严禁进入下一章**

### 3.3 去AI味润色（两遍式流程）

**第一遍：清除AI模式**

检测7大类问题：
1. AI高频词汇（不禁/仿佛/映入眼帘等）
2. 弱化副词泛滥（微微/淡淡/缓缓等）
3. 意义膨胀（意义深远/前所未有等）
4. 通用结论套话（未来可期/前途无量等）
5. 论文式段落结构（不难看出/由此可见等）
6. 正式语体入侵（于是乎/与此同时等）
7. 排比三连过多

**第二遍：AI自审**

对修改稿提问：
> "这段文字哪些地方还是明显AI生成的感觉？"

列出3-5条具体问题，再次修改后输出最终版

### 3.4 反向刹车机制

解决AI过度"帮助解决问题"的倾向：

- **非终局章节禁止解决主线核心冲突**
- **每章必须新增至少一个未解决的次要问题**
- **章末必须留下悬念钩子**（疑问型/危机型/转折型）

### 3.5 事件矩阵与冷却

防止剧情模式化：

| 事件类型 | 冷却期 |
|----------|--------|
| conflict_thrill（冲突爽点）| 2章 |
| bond_deepening（人物羁绊）| 1章 |
| faction_building（势力经营）| 2章 |
| world_painting（风土人情）| 3章 |
| tension_escalation（危机升级）| 2章 |

**规则**：刚用过的类型在冷却期内不得作为主Beat，每5章必须至少出现一次羁绊或风土人情

### 3.6 节奏三档制

| 档位 | 说明 | 频率要求 |
|------|------|----------|
| 慢档 | 铺垫/羁绊，主线零推进 | 每3-4章≥1章 |
| 中档 | 次要矛盾升温未爆发 | ≥60%章节 |
| 快档 | 主线突破 | 每卷≤2-3次 |

**规则**：快档后必须有慢/中档缓冲，禁止连续快档

## 四、长期记忆解决方案

### 4.1 问题背景

长篇小说（100万字以上）面临的核心挑战：
1. **设定遗忘** — 写到后面忘记前面的设定
2. **角色漂移** — 角色性格、位置、能力前后矛盾
3. **剧情断裂** — 伏笔忘记回收，支线悬而未决
4. **时间线错乱** — 故事时间推进不合理

### 4.2 解决架构

#### 第一层：五步质量门禁（每章强制）
```
/更新记忆 → /检查一致性 → /风格校准 → /校稿 → /门禁检查
```

#### 第二层：RAG剧情检索
- **粗筛**：BM25风格TF-IDF，筛选候选池（默认8个）
- **精排**：语义重排，返回Top-K（默认4个）

#### 第三层：知识图谱
- 节点类型：角色、地点、势力、物品、事件、伏笔、世界观规则、力量体系
- 边类型：同盟、敌对、师徒、从属、情感、归属、位于、引发、铺垫、持有
- 自动更新：每章写后自动提取信息回写图谱
- 级联更新：修改大纲时自动计算影响范围

#### 第四层：大纲锚点
- 全局进度条，章节推进配额约束
- 越界直接触发门禁失败

#### 第五层：跨Agent审核
- 双智能体交叉验证（Claude写Codex审，反之亦然）
- 批处理审核：每10章由"极严苛老书虫"人设审核官做三维度体检
- 防死循环：单章最多3轮审核，连续3章"有条件通过"强制暂停

## 六、关键发现

### 6.1 铁律约束

5条不可违反的规则：
1. 禁止跳过强制章节闭环
2. 禁止绕过开书前确认
3. 禁止混淆正文与元信息
4. 禁止门禁失败后继续写作
5. 禁止任意修改主线规划

### 6.2 低上下文策略

- 写前默认只读：`novel_plan.md` + `novel_state.md`
- 单章前置读取上限：**最多4个文件**
- RAG检索只返回Top-K片段，不回读整章
- 每10章做一次深度压缩与风格校准

### 6.3 多步流水线写作

将"写一章"拆解为多步协作：
```
Beat Sheet生成 → Beat扩写（填血肉）→ 章节合成 → 门禁流程
```

强制限制单次生成的剧情跨度，让每个场景充分展开

### 6.4 风格指纹系统

- 从样章提取风格特征
- 建立风格档案库
- 跨项目复用风格
- 文风偏移检测与校准
