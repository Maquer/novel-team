## 二、核心创新

### 2.1 合同树（Contract Tree）

> 每个节点带结构化进口/出口（账目/线头/事实三类字段），「上一块出口 == 下一块进口」由程序逐字段比对，不靠模型自觉。

```
种子（一句话设定）
  → 根合同（全书进口/出口：账目、线头、事实）
  → 里程碑链（全书拆成30节推进链，程序校验相邻节咬合）
  → 逐章细纲（每章发散3个候选，程序按判据选优）
  → 正文（每章3个候选，硬闸淘汰 + 文风闸比较）
  → 评审（模型只报带正文原句证据的问题，分数由程序按扣分表算）
  → 自动返修 → 回炉发散 → 仍不行才标MANUAL等人
```

### 2.2 多候选程序选优

**细纲三候选裁判纯程序**：
- 收回章数
- 到期伏笔是否安排回收
- 钩子查重
- 账目推进配比

**正文三候选先过硬闸**：
- 接缝重复
- 元语言泄漏
- 黑名单穿帮词

### 2.3 评审机制

> 模型只报「问题 + 正文原句引证」，没有原句的问题程序直接剔掉；分数由程序按扣分表从可数的证据推出来，谁都能复核。

### 2.4 硬账台账

> 兵力、钱粮这类可计数状态由程序记账、程序对数——正文里出现的数字与台账不符当场报，防「上一章119发子弹、下一章12发」这类跳变。

### 2.5 熔断 + 三级自愈

```
连续5章被判「需人工」或滑窗10章里6章坏
  → 写HALT.md停跑（连片坏章是同一个根子在批量产废品，继续烧没有意义）
  → 守护先自动返修
  → 返修不动就回炉发散（回滚坏段、细纲重新三候选）
  → 同段回炉两轮仍坏才标MANUAL等人
```

## 四、关键发现

### 4.1 程序校验 vs 模型自觉

> 「上一块出口 == 下一块进口」由程序逐字段比对，不靠模型自觉。

这是本项目最深刻的工程洞察：**让程序做程序能做好的事，让模型做模型擅长的事**。

### 4.2 多候选选优的成本控制

```
细纲三候选 → 纯程序裁判（零调用）
正文三候选 → 硬闸淘汰（零调用）+ 文风比较（一次评审调用）
```

### 4.3 硬账台账的数值一致性

> 防「上一章119发子弹、下一章12发」这类跳变

这个细节非常实用，也是目前我们工具链的空白点。

### 4.4 熔断机制

> 连片坏章是同一个根子在批量产废品，继续烧没有意义

这是一个非常重要的工程决策：**知道何时停下来比知道如何继续更重要**。
