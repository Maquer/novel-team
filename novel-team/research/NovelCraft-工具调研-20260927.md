## 一、工具概述

### 1.1 基本信息

| 项目 | 内容 |
|------|------|
| 名称 | NovelCraft |
| 定位 | 中文长篇小说创作 Skill |
| 核心理念 | "规则越密，越容易被跳过或走形式" |
| 核心问题 | **写这一章时该怎么决定** |
| Stars | 0 ⭐（新项目）|
| License | MIT |

### 1.2 核心特色

1. **虚拟作家人格**：每章开写前读一遍，保持人格一致性
2. **故事承诺六件事**：主角追求、根本阻力、成败代价、读者体验、核心问题、主题张力
3. **三级纲要**：卷 → 幕 → 章，每级有明确验收标准
4. **状态快照**：current_state.md 只回答"此刻接着写要记得什么"
5. **去AI味12条纪律**：写前过一遍，写后回看一遍
6. **工程极简主义**：只有两个脚本（init_project/build_release），不做质量门禁

## 二、架构设计

### 2.1 工作流

```
人格与故事承诺 → 落人格覆盖层 → 卷定方向 → 卷推演 → 幕定因果 → 章前规划
→ 章纲 → 草稿 → 用户确认定稿 → 更新状态
→ 从真实结果规划下一幕
```

### 2.2 项目骨架

```
state/
  author_persona.md     人格：每章开写前读一遍
  story_foundation.md   全书主线、故事承诺、主题命题、世界观与规则、Canon、人物引擎
  current_state.md      此刻接着写需要记得什么
  memory.md             项目状态、最后定稿章与当前工作章、阶段、下一步、用户偏好

workspace/
  volumes/    卷纲
  acts/       幕纲
  outlines/   章纲
  drafts/     草稿
  chapters/   定稿
  summaries/  摘要
  rehearsals/ 卷推演
```

### 2.3 关键设计原则

| 原则 | 说明 |
|------|------|
| **最小形态** | 没有检查，没有门禁，没有评分 |
| **文学判断由模型完成** | 正文定稿由用户确认 |
| **稳定内核，不冻结姿态** | 不变量层稳定，姿态层因场景变化 |
| **设定后置** | 人物碰到规则才讲，不提前介绍 |
| **Canon Registry** | 不可逆事件、硬规则、身份唯一事实当场登记 |

## 三、核心创新

### 3.1 作家人格系统

**不变量层**（每章必读，3-6条）：
- 注意力顺序：进入一场戏，先看【】，最后看【】
- 镜头纪律：镜头站在【】身上；【】的内心永远不进
- 信息控制：【】先给读者，【】后给人物
- 代价管理：胜利由【】结算；成长由【】结算
- 收束方式：一章停在【】
- 材料取舍：面对一场戏，删【】，留【】

**姿态层**（按场景类型查表）：
| 场景类型 | 速度 | 句长 | 段落 | 对白占比 | 描写配比 | 本章禁用 |
|---------|------|------|------|---------|---------|---------|
| 战斗 | 慢，动作分解 | | | | | |
| 日常 | | | | | | |
| 仪式/葬礼 | | | | | | |
| 独白/内省 | | | | | | |
| 转场 | | | | | | |

**冲突优先级**：
```
不变量层 > 红线 > 风格基调 > 姿态层与技法卡
```

### 3.2 去AI味12条纪律

**写前过一遍（场景纪律）**：

| 纪律 | 规则 | 正反例 |
|------|------|--------|
| 1. 眼前有事 | 人物每场只办一件眼下的事 | ❌ 他是冷漠的人 ✅ 他把门关上了 |
| 2. 视角细节 | 细节跟着人物视角走 | ❌ 房间里陈设简朴 ✅ 他数了数墙上的裂缝 |
| 3. 对白做事 | 说话在试探、遮掩、说服 | ❌ "你昨天去哪了？""见朋友。" ✅ 他没抬头。"忙。" |
| 4. 设定后置 | 规则等人物碰到再讲 | ❌ 灵力分九阶... ✅ 他攥紧拳头，骨头缝松了一下 |
| 5. 反乒乓链 | 300字内一问一答≤8拍 | ❌ 连续八轮问答 ✅ 第三轮他站起来倒了杯水 |
| 6. 冷开场 | 章首用对话或动作顶第一行 | ❌ 清晨的阳光... ✅ 他把手机按掉 |
| 7. 硬结尾 | 章尾停在动作/物件/台词 | ❌ 他终于明白勇气... ✅ 他拍了一下，没拍掉 |
| 8. 拒微闭环 | 300字内不走完"出现→确认→执行→反馈" | ❌ 收到消息→确认→回电→约定 ✅ 手机震了，他没回 |
| 9. 五行卡 | 写前回答五个问题自检 | 人物想办什么？阻力从哪来？演到哪停？ |
| 10. 闲笔有来路 | 删掉它，这场信息/气氛要受损 | ❌ 树荫挪了位置 ✅ 他数了一遍瓶子，少了一瓶 |
| 11. 时间密度 | 一章之内至少一处快、一处慢 | ❌ 收拾行李连夜赶路三天后到了 ✅ 带子卡了两次 |
| 12. 情感配给 | 一场只给一个情绪峰值 | ❌ 又愤怒又悲伤 ✅ 手很稳，才发现扶手是凉的 |

### 3.3 故事承诺六件事

每本书必须回答这六件事：

1. **主角追求**：他想要什么？
2. **根本阻力**：什么挡着他？
3. **成败代价**：失败了会失去什么？
4. **读者长期体验**：读者长期想看什么？
5. **核心问题**：这本书在问什么？
6. **主题张力**：命题与反命题的对立？

### 3.4 卷推演方法

卷纲写完后必须做卷推演验证：

**五件事核对**：
1. 卷纲推不推得出每一章？
2. 冲突哪一层松了？
3. 每条人物弧线的落点能否抵达？
4. 新发现的场次与意外怎么分派？
5. 和已登记Canon冲不冲突？

**断点法定卷数**：
- 0个断点 → 1卷
- 1个断点 → 2卷
- 2个断点 → 3卷
- 3个断点 → 4卷
- 4+断点 → 5卷以上

### 3.5 Canon Registry

**四类必须登记**：
- 身份唯一事实
- 硬规则（用过后不能改）
- 唯一结算锚点
- 不可逆事件

**格式**：`ID｜类别｜事实｜来源章`

## 六、关键发现

### 6.1 反模式：规则密度陷阱

> "一套完整的流程系统——7个脚本、10类一致性检查、机械AI味体检、幕末归档快照——会让写3000字正文的流程成本接近甚至超过正文本身。规则密度过高，反而降低了规则的实际约束力。"

### 6.2 人格覆盖层（AGENTS.md）

人格定稿后，把不变量层与硬规则写进项目的 `AGENTS.md`：
- 每个会话被自动加载
- 人格从此常驻，不只动笔时才在场
- 只装不变量层：身份句、决策句 + 一步不能让的硬规则

### 6.3 技法卡回验四态

| 状态 | 说明 |
|------|------|
| 已回验 | 引文能在原语料命中 |
| 上游已校验 | 机制可读，但引文未经本侧复核 |
| 缺材料待回验 | 连证据锚点都没有 |
| 回验失败 | 舍弃并记原因 |

### 6.4 角色发声推导下一卷

> "让现有角色说话，从他们行动方向的交汇点里推出主线。至少两个角色的'现在想做的事'指向同一个矛盾点，主线就成立了。"

## 七、结论与建议

### 7.1 核心价值

NovelCraft是一个**极简主义的反套路**工具。它反对过度工程化，认为：
- 规则越密越容易被跳过
- 文学判断应由模型完成
- 定稿权必须留在用户手中

其作家人格系统和去AI味12条纪律是目前同类工具中**最系统化、最具实操性**的设计。

### 7.2 与小说团队的关系

| 维度 | 评估 |
|------|------|
| **可运行** | ✅ Python脚本，iSH完全可行 |
| **可借鉴** | ✅ 高度可借鉴（人格系统+12条纪律）|
| **可复用** | ✅ 部分可复用（模板设计、状态管理）|

### 7.3 推荐集成路径

1. **短期**：集成去AI味12条纪律到humanizer-check
2. **中期**：扩展作家人格模板，支持三轨结构
3. **长期**：实现Canon Registry和卷推演验证
