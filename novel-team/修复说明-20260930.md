## 二、逐项修复明细

### 2.1 tools/gate-check.py（门禁核心）

1. **ai_tone 死 warning 分支**（P1）
修前 `15 < tier_1a ≤ 15.75 → warning` 永远不可达（tier_1a 恒为整数）。
修后：阻断语义不变（`tier_1a ≥ 16 → fail`）；warning 改为"接近阈值"预警（`13 ≤ tier_1a ≤ 15`）。
预警线 `warn_at=13` 为经验取值，已放入 `GATE_CONFIG["ai_tone"]`，可自行调整。

2. **_check_modify 未执行 logic_review**（P1）
文件自身的 `MODIFY_REQUIRED_GATES` 声明修改模式必须执行 logic_review，但 `_check_modify()` 漏掉了。
修后：补上调用，与声明一致；docstring 同步更新。

3. **_check_logic_review 换目录静默 pass**（P1）
原经 `python -m tools.logic-review` 拉起但未指定 cwd，换工作目录即 ModuleNotFoundError，
而 except 分支静默置 pass——等于留了一个 bypass 后门。
修后：subprocess 加 `cwd=<工具树根目录>`；异常时记 `warning` 并写明原因，不再静默。

4. **protocol 同时在 p0_gates 和 p2_gates**（P3）
修后：从 p2_gates 移除，保留 P0（此前按 p0→p1→p2 顺序匹配已恒为 P0，属死配置清理）。

5. **接入 anti-ai-12 作 P2 建议**（P1）
原门禁完全不调用 anti-ai-12 的 12 条纪律。修后新增 `_check_disciplines()`，
以 in-process 方式（importlib 加载，文件名含连字符无法常规 import）直接调用 `check(text)`，
命中进 `p2_suggestions`，永不阻断；import 失败只记一条提示，不影响主流程。
只做到 P2 建议级；是否升级为阻断项由你决定。

6. **补 SCENE_JUMP_PATTERNS / SCENE_JUMP_THRESHOLD 定义**（P0，验证中新发现）
原包 `_check_cliche` 引用了这两个常量但从未定义，**每次 check() 跑到此处即 NameError 崩溃**——
门禁主流程根本走不完。已补上 5 组场景硬切模式与阈值（3 处）。
模式与阈值为经验取值，命中仅进 P2 建议。

7. **顶层 p0_failures 与 evaluation 同步**（P0，回归测试中新发现）
09-29 修复只同步了 `evaluation.p0_failures`，顶层 `p0_failures/p1_warnings/p2_suggestions`
仍恒为空数组——正是 09-28 历史门禁"顶层通过、子检查 fail"的表现层残留。
只读顶层的调用方（test-degradation、外部工作流）会误判为无问题。
修后：check() 合并 evaluation 时同步顶层三字段；test-degradation 第 6 节断言通过。

### 2.2 tools/quality-gate.py（门禁编排器）

1. **新增 --strict 模式**（P0）
修前：gate-check 返回 passed=False 也被转成"质量债务"继续放行；若生产入口是本文件，
gate-check 的阻断修复会被外层短路。
修后：`--strict` 下门禁未通过直接 exit 非零阻断，不转债务。
**默认仍为宽松模式**（行为不变，避免误伤现有流程）；生产入口建议用 `--strict`。
到底生产走的是 `gate-check.py` 还是 `quality-gate.py`，仍需你在 OpenMinis 中确认一次。

2. **账本路径统一**（P1）
`commit_to_ledger` 原写 `BASE_DIR/.ledger/<novel>/facts.json`，
而 gate-check 读的是 `<root>/ledger/<novel>/facts.json`——写入的数据门禁永远读不到。
修后：统一为 gate-check 读的路径，经 project_guard.resolve() 解析。

3. **frontmatter 解析改用正则**（P1）
原 in_meta 状态机逻辑错误（metadata 常解析为空、body 切分不可靠）。
修后：只剥离文件开头的第一个 `---` 块。

4. **run_guard_v6 缺文件不再自动建空文件**（P2）
修后：缺文件报 warning 并跳过该步。

5. **BASE_DIR 改从 project_guard 统一入口**（P0，验证中新发现）
本文件自带硬编码 `BASE_DIR=/var/minis/shared/novel-team`，与 project_guard 的
`NOVEL_TEAM_ROOT` 环境变量覆盖脱节，异机/测试环境下会去拉不存在路径的 gate-check。
修后：`from project_guard import BASE_DIR`（单文件拷贝运行时回退 env 读取）。

6. **质量债务导入修复**（P2，验证中新发现）
原 `from quality_debt import gate_result_to_debt` 恒失败——文件实际叫 `quality-debt.py`
（连字符非法模块名），债务集成永远走 except。修后改用 importlib 按文件路径加载。

### 2.3 tools/project_guard.py（唯一路径入口）

1. **BASE_DIR 支持环境变量覆盖**（P0）
`BASE_DIR = Path(os.environ.get("NOVEL_TEAM_ROOT", "/var/minis/shared/novel-team"))`。
OpenMinis 下默认值即 `/var/minis` 规范路径，功能不变；异机/测试环境可覆盖。
2. **`rm -rf` 改 `shutil.rmtree`**（P1 安全）
不再经 shell 拉起 rm，走安全 API。

### 2.4 tools/test-degradation.py（回归测试）

1. 全部 subprocess 加 `timeout=120`（P1；原无 timeout，可能永久挂起）。
2. 新增断言用例：构造 tier_1a=39 的章节跑 gate-check CLI，
断言 `passed == False` 且 `p0_failures` 含 ai_tone 条目（P1；原只认退出码 0/1）。

### 2.5 tools/novel-humanizer.py（门禁实际调用的 AI 味检测器）

1. **--threshold 死参数接线**（P1）
原 CLI 解析了 `--threshold` 但从未使用。修后 `detect_all()` 接受 threshold，
分级阈值按其等比缩放；默认 15.0 时行为与原来完全一致。
2. **_strip_markdown 剥离 frontmatter**（P2）
原元数据块会被当正文扫描，污染分数。

### 2.6 tools/logic-review.py（9 项逻辑审查）

1. **modern_item_org_conflict 补 v2.0 映射**（P1）
原只有 v1.0 的"天剑宗"，v2.0 正文（剑心宗/血海宫）下该规则永久失效。
修后：内置表同时覆盖 v1.0 与 v2.0，并优先从 config/logic-rules.json 读取。
v1/v2 并存（旧数据仍可能引用 v1.0）。
2. **divine_sense_boundary 降误报**（P1）
原"看到/发现/感到/神色/脸色"等高频词同段即判 error。
修后：弱感知词要求**同句**才判，强感知词（感应/察觉/神识/灵觉）保持同段。
3. **time_contradiction 时间信号可配置**（P1）
原 start_signals 硬编码第 2 章专用词。修后从 config 读取，无则回退通用词，
并支持 `--chapter` 参数按章节覆盖。

4. **constitution_sword_match 降误报**（P1，修复组复核中新发现）
`rule_constitution_sword_match` 硬编码强/弱感知词混装且一律"同段即判"，
与 divine_sense 修复前相同的误报模式。修后沿用同一强/弱分级：
强感知词保持同段判定，弱感知词收紧为同句判定（人物名、触发词、弱感知词须在同一句内）。

### 2.7 tools/wordcount-check.py（独立字数 CLI）

1. **口径与门禁统一**（P1）
原默认"纯汉字计数、最低 3000"，与门禁"全非空白字符、fail<1350/目标 2500"打架。
修后：默认计数函数与 gate-check 一致；旧口径保留为 `--chinese-only` 选项；
默认阈值对齐门禁。门禁口径为唯一执法口径。
2. 删除尾部不可达的重复 return（P2）。

### 2.8 tools/humanizer-9d.py

- **时代词表去重**（P2）：原 humanizer-9d 自带一份现代词表，与 logic-review 的
`era_words`（本就从 `config/logic-rules.json` 读取）不一致且互相漏检。
修后 humanizer-9d 统一从 `config/logic-rules.json` 的 `era_words.words` 读取，
失败回退内置并与内置独有词取并集（避免覆盖面倒退）。
注：anti-ai-12.py 经全文核查并无时代词表（"手机"仅出现在纪律示例文案中），无需改动；
给它加时代词检测会改变其"创作纪律清单"定位，超出本次范围。

### 2.9 tools/fact-ledger.py（事实账本）

1. **入参校验**（P1）：category/content/source 非空校验，空值抛 ValueError；
source 黑名单 `["测试", "test"]`，命中拒绝写入（`--allow-test` / `allow_test=True` 可放行）。

4. docstring 与新命令同步。

### 2.10 tools/world-pack.py（世界包管理器）

1. **add_relation 补 to 键**（P1）

2. `check_consistency` 对历史缺 to 的关系报 warning（而非静默跳过）。

### 2.11 tools/world-sync.py（事件驱动同步器）

这是部分修复；完整的版本感知同步架构需另行设计。

2. **_load_characters 硬编码路径修复**（P2）：原写死 `projects/my-novel/...` 忽略 novel_id；
修后经 `project_guard.resolve(novel_id)` 解析。
3. **_load_world_pack 首包任意选择修复**（P2）：原取目录第一个 JSON；
修后优先选与项目世界名匹配的包，无匹配才回退，并记 warning。
