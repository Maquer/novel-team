# 小说团队 · 创作流程SOP（方案C+版 v2.1）

> 基于团队讨论决议（2026-09-28），采用方案C+（混合流程增强版）
> 核心变更：融合写作岗 + 强制自检 + 主编抽检 + 分级门禁

---

## 整体流程（方案C+）

```
┌─────────────────────────────────────────────────────────────┐
│                   方案C+ 混合流程增强版                        │
├─────────────────────────────────────────────────────────────┤
│  大纲确认 → 关键节点检查 → 全文创作 → 自检 → 主编审核 → 门禁 → 发布 │
│   (策划)      (写手)       (创作岗)  (创作岗)  (主编)   (工具)  (运营) │
└─────────────────────────────────────────────────────────────┘
```

### 流程对比

| 方案 | 流程 | 质量 | 效率 | Token消耗 | 状态 |
|------|------|------|------|-----------|------|
| A（原流程） | 辅助岗写初稿→扩写→主笔精修 | ⭐⭐⭐⭐⭐ | ⭐⭐ | 高 | 已弃用 |
| B（融合） | 创作岗一次写完 | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 低 | 风险太高 |
| **C+（推荐）** | **创作岗全文→自检→主编抽检→门禁** | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | 中 | **✅ 已上线** |

### 字数控制
- **正文目标**：每章 2000-4000 字（按章节类型分类）
  - 过渡章：2000-2500 字（场景切换、铺垫）
  - 战斗章：2500-3500 字（完整战斗）
  - 高潮章：3000-4000 字（重大事件）
- **自检门槛**：S≥85（底线：时代适配度≥60 + 对话自然度≥60）
- **精品门槛**：S≥90 可直接通过

- 世界观设定

### 输出

- 关键转折点标记

### 工具
```bash

# 节拍校验（必须在大纲确认后执行）

```

### 决策点
- [ ] 三幕式结构是否完整？
- [ ] 爽点层级（L1-L4）是否标注？
- [ ] 伏笔是否埋设到位？
- [ ] **节拍校验通过？**（前3章破冰 / 压抑≤2章 / L2间隔≤5章 / L4每卷1次）

## 阶段三：全文创作（创作岗，持续）

> ⚠️ **方案C+ 核心变更**：创作岗合并原辅助岗+主笔岗职责，一次生成完整章节

### 输入
- 确认的大纲
- 关键节点检查结果
- 上下文（前后章节内容，最多4个文件）
- 角色档案（仅限本章出场角色）

### 输出
- 完整章节正文（2000-3000字）

### 创作要求
1. **开篇钩子**：首段必须有吸引力
2. **结尾悬念**：末段必须留下钩子
3. **节奏紧凑**：避免拖沓，每段有推进
4. **无AI味**：禁用套话、滥用比喻、机械化表达
5. **淡化时间，事件驱动**（09-29 新增）：不靠「第X天/第X周」日历报数推进，改由异常、悬念、冲突驱动。时间词用模糊节奏（「入夜」「没多久」「又过了一阵」），精确数字只用于**故事装置**（如「七格凹槽」=悬念），不用于线性计数。`gate-check cliche` 已自动检测日历报数。
6. **长篇节奏控制**（09-29 新增，防短篇陷阱）：
   - 每章目标字数：**2000-3000字**（门禁 `soft_min` 1500，低于1500字 P1 警告）
   - 每卷目标章节：**10-15章**（单卷2-4万字）
   - 全书目标总字数：**10万字起**（5卷×2万字）
   - 长线钩子：每卷末尾必须埋下**卷末大钩子**（非章末小钩子），让读者追下一卷
   - 卷间节奏：起（1-3章）→承（4-8章）→转（9-12章）→合（13-15章）
   - `gate-check` 已升级字数门禁（见 GATE_CONFIG.word_count）

7. **场景过渡连贯**（09-29 新增，防剧本式硬切）：
   - 场景切换必须有**过渡桥段**：行走、等待、天气变化、人物动作、感官转换
   - 禁止**硬切**：「---」之后直接新场景，无过渡（像剧本分场）
   - 时间/空间转换要**自然流动**：用模糊词（「没多久」「走了几步」「天擦黑」）而非数字报时
   - 示例对比：
     - ❌ 硬切：「---\n她走进房间。」
     - ✅ 连贯：「她走出那座楼，脚步很慢。走了几步，抬头看见东宫的屋檐在夕阳下泛着光。」
   - `gate-check cliche` 将检测场景跳跃（待实现）

### 扩写模板（字数不足时适用）

当章节字数低于 2000 字时，按以下结构扩写：

```
1. 场景开场（200-300字）
   - 环境描写：地点、时间、氛围
   - 感官细节：视觉、听觉、嗅觉、触觉
   - 氛围营造：紧张、压抑、宁静等

2. 人物互动（300-500字）
   - 对话：符合角色性格，避免标签式
   - 动作：具体、有细节，避免空洞
   - 心理：内心描写，展现角色动机

3. 冲突发展（300-500字）
   - 事件推进：情节向前发展
   - 障碍出现：新困难或挑战
   - 紧张感：悬念、危机、压力

4. 高潮/转折（200-300字）
   - 关键事件：重要决定或行动
   - 情感爆发：角色情绪变化
   - 悬念设置：为下一章埋下伏笔

5. 章末钩子（100-200字）
   - 新威胁：新的危险出现
   - 新问题：未解决的悬念
   - 新悬念：引起读者好奇
```

**扩写原则**：
- ✅ 增加实质内容：场景、人物、冲突、情感
- ✅ 具体描写：感官细节、动作细节、心理细节
- ❌ 简单加水：重复、空洞、无意义
- ❌ 堆砌辞藻：华丽但无实质

## 阶段四：自检（创作岗主导，每章必须执行）

> ⚠️ **方案C+ 核心变更**：创作岗必须完成结构化自检，禁止跳过

### 自检流程（按顺序执行）

```bash
# Step 1: 九维质检评分
python3 tools/humanizer-9d.py --chapter-file chapters/ch{N:03d}.md --json \
  > reports/humanizer-ch{N}.json

# Step 2: 四问关键节点检查（开头/中段/结尾）
python3 tools/paragraph-four-questions.py check --novel-id my-novel --chapter {N} --section opening
python3 tools/paragraph-four-questions.py check --novel-id my-novel --chapter {N} --section middle
python3 tools/paragraph-four-questions.py check --novel-id my-novel --chapter {N} --section closing
python3 tools/paragraph-four-questions.py verify --novel-id my-novel --chapter {N}

# Step 3: 门禁检查
python3 tools/gate-check.py check --file chapters/ch{N:03d}.md --mode write

# Step 4: 因果校验
python3 tools/guard-v6.py check --novel-id my-novel --chapter {N}

# Step 5: 同步 HTML 备份
python3 tools/md-to-html-sync.py sync --novel-id my-novel --file chapters/ch{N:03d}.md
```

### 自检结构化表格（必须填写并存档）

| 检查项 | 结果 | 备注 |
|--------|------|------|
| 九维总分 S | __/100 | 需≥85 |
| 时代适配度 | __/100 | **底线≥60** |
| 对话自然度 | __/100 | **底线≥60** |
| 四问（开头） | PASS/FAIL | 谁在场/刚在哪/为什么/信息来源 |
| 四问（中段） | PASS/FAIL | 同上 |
| 四问（结尾） | PASS/FAIL | 同上 |
| 门禁检查 | PASS/FAIL | 字数/AI味/事实冲突 |
| 因果校验 | PASS/FAIL | error必须修正 |

### 自检存档要求
- 自检报告保存到 `reports/self-check-ch{N}.json`
- 建立问责追溯机制
- **每月盲审抽检20%**

## 阶段五：主编审核（主编岗，抽检制）

> ⚠️ **方案C+ 核心变更**：从"每章必审"转型为"抽检制+状态机约束"
>
> **约束原则**：不依赖日历时间（AI团队无真实时间流逝），改用状态机控制流程阻塞与推进。

### 审核触发条件（状态转移入口）

| 条件 | 状态转移 |
|------|---------|
| 首次创作本章题材 | `创作完成` → `待审核`（必须） |
| 九维评分 < 84 | `创作完成` → `待审核`（必须） |
| 九维评分 ≥ 84 | 🎲 30% 概率 → `待审核`，70% → `已审核`（默认通过） |
| 其他作者连续3章 S≥90 | 🎲 10% 概率 → `待审核`，90% → `已审核`（默认通过） |

### 状态机定义

```
┌─────────────────────────────────────────────────────────────┐
│                   章节审核状态机                             │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│   创作完成 ──┬──→ 待审核 ──→ 审核通过 ──→ 门禁检查           │
│              │      │                                        │
│              │      └──→ 审核驳回 ──→ 回炉创作 ──→ 创作完成  │
│              │                                                │
│              └──→ 已审核（默认通过）──→ 门禁检查              │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 阻塞规则（状态机硬约束）

| 规则 | 说明 |
|------|------|
| **阻塞** | 章节处于 `待审核` 状态时，下一章创作**必须阻塞**，等待审核结果 |
| **自动通过** | 审核被调用后，**连续 3 轮无反馈** = 默认通过（`待审核` → `已审核`） |
| **驳回处理** | 审核发现重大问题 → `审核驳回` → 回炉创作（重置为 `创作完成`） |
| **优先级** | 首次/S<84 的章节优先处理（队列排序） |

### 审核流程

```yaml
# editor-review-prompt.yaml
system:
你是一位资深网文主编，正在审核一章稿件。
你的职责：
1. 结构性审查（节奏、伏笔、人物弧光）
2. 逻辑一致性审查（事实冲突、时间线矛盾）
3. 红线问题审查（时代漂移、人物OOC）
4. 审核意见单（指出问题+修改建议）

注意：形式问题（错别字、标点）由创作岗自检负责，主编不重复检查。

user:
下面是待审核章节。
{chapter_text}

下面是九维评分结果。
{humanizer_result}

assistant:
开始审核...
```

### 状态变更命令

```bash
# 检查章节审核状态
python3 tools/gate-check.py status --novel-id my-novel --chapter {N}

# 手动标记审核通过（仅在连续3轮无反馈时）
python3 tools/gate-check.py approve --novel-id my-novel --chapter {N}

# 驳回并回炉
python3 tools/gate-check.py reject --novel-id my-novel --chapter {N} --reason "逻辑矛盾"
```

## 阶段六：门禁检查（强制，每章必经）

> ⚠️ 任何章节必须通过门禁才能发布

### 分级门禁规则

```
┌─────────────────────────────────────────────────────────────┐
│                    分级门禁规则                              │
├─────────────────────────────────────────────────────────────┤
│  S ≥ 90  →  直接通过（精品章）                               │
│  85 ≤ S < 90  →  主编抽检10%                                │
│  S < 85  →  必须回炉，不允许通过                            │
└─────────────────────────────────────────────────────────────┘
```

### 红线问题（自动拦截）

以下红线问题必须在自检阶段发现并修正：

| 红线类型 | 检测工具 | 处理方式 |
|---------|---------|---------|
| 时间线矛盾 | `logic-review.py` | 强制修正 |
| 人物状态矛盾 | `fact-ledger.py check` | 强制修正 |
| 核心设定漂移 | `guard-v6.py check` | 强制修正 |
| 时代适配度 < 60 | `humanizer-9d.py` | 强制修正（一票否决） |
| 对话自然度 < 60 | `humanizer-9d.py` | 强制修正（一票否决） |

### 门禁检查顺序

| 步骤 | 工具 | 命令 | 失败处理 |
|------|------|------|---------|
| 1 | 事实账本 | `python tools/fact-ledger.py add-fact ...` | 记录本章事实 |
| 2 | 一致性检查 | `python tools/fact-ledger.py knowledge check ...` | 发现冲突则中止 |
| 3 | 逻辑审查 | `python tools/logic-review.py check --file chapter.md` | 错误必须修正 |
| 4 | 门禁检查 | `python tools/gate-check.py check --file chapter.md` | fail阻断 |
| 5 | 因果校验 | `python tools/guard-v6.py check --novel-id my-novel --chapter {N}` | error必须修正 |
| 6 | 账本更新 | `python tools/fact-ledger.py account add ...` | 记录物品变化 |

## 质量门禁（每章必经）

```
更新记忆 → 检查一致性 → 逻辑审查 → 门禁检查 → 因果校验 → 账本更新
   ↓           ↓           ↓          ↓          ↓          ↓
 同步状态    冲突检测    logic-review  gate-check  guard-v6   ledger
```

**任何一步未通过，严禁进入下一章**

### 九维评分阈值

| 等级 | 分数 | 状态 | 处理 |
|------|------|------|------|
| S | ≥90 | 🟢 优秀 | 直接通过（精品章） |
| A | 85-89 | 🟢 良好 | 主编抽检10% |
| B | 70-84 | 🟡 中等 | 主编必审 + 必须修改 |
| C | 60-69 | 🟠 较差 | 回炉重写 |
| D | <60 | 🔴 不合格 | 禁止发布 |

### 底线维度一票否决

以下两个维度必须≥60分，否则即使总分达标也不允许通过：
- **时代适配度**：禁用词、物价合理性、科技产物出现时间
- **对话自然度**：口语省略、方言痕迹、符合角色性格

## 上下文管理策略

### 低上下文原则
- 写前默认只读：`novel_plan.md` + `novel_state.md`
- 单章前置读取上限：**最多4个文件**
- RAG检索只返回Top-K片段，不回读整章
- 每10章做一次深度压缩与风格校准

### 上下文注入顺序
1. 小说简介（固定）
2. 前后章节上下文（动态）
3. 本章大纲/设定（动态）
4. 创作指令（动态）
