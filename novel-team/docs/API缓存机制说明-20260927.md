# API缓存机制说明

> 编写时间：2026-09-27
> 适用场景：小说团队LLM创作流程

---

## 一、什么是API缓存？

**API缓存** = 把已经调用过的API结果保存起来，下次遇到相同或相似请求时，直接返回缓存结果，不再重新调用API。

### 通俗比喻

> 就像你问老师同一个问题：
> - **无缓存**：每次问都要重新等待老师思考回答
> - **有缓存**：老师记住你的问题，下次直接说"上次回答过，答案是XXX"

---

## 二、为什么需要API缓存？

### 2.1 成本问题

| 场景 | 无缓存 | 有缓存 |
|------|--------|--------|
| 每章创作 | 调用3次API（初稿+分析+检查）| 调用1次API（其余读缓存）|
| 100章累计 | 300次调用 | 100次调用 |
| Token消耗 | 30万Token | 10万Token |
| 费用（按$0.002/千Token）| $600 | $200 |
| **节省** | - | **66%** |

### 2.2 效率问题

| 场景 | 无缓存 | 有缓存 |
|------|--------|--------|
| 单次API调用 | 平均5秒 | - |
| 读取缓存 | - | 平均0.01秒 |
| 100章创作 | 500秒（8分钟）| 500秒 + 100×0.01秒 ≈ 501秒 |
| **节省时间** | - | **约8分钟** |

### 2.3 稳定性问题

- API有时限流（Rate Limit）
- API可能临时故障
- 缓存可以作为**降级方案**，保证流程不中断

## 三、在小说团队中的应用场景

### 3.1 提示词缓存

**场景**：同一章节类型使用相同的提示词模板

```python
# 示例：玄幻开篇章节的提示词
prompt_template = """
你是一个玄幻小说作家。请根据以下设定创作开篇：
- 世界观：{world}
- 主角：{protagonist}
- 场景：{scene}
- 要求：2000字，展现主角性格，埋下伏笔

【系统提示词】
你是一位资深网文作家，擅长...
"""

# 缓存键：提示词内容的哈希值
cache_key = hashlib.md5(prompt_template.encode()).hexdigest()

# 第一次调用：计算+存储
result = call_llm(prompt_template)
cache.set(cache_key, result, expire=3600)  # 缓存1小时

# 第二次调用：直接读缓存
cached_result = cache.get(cache_key)
```

**收益**：相同提示词不再重复调用，节省50%以上成本

---

### 3.2 剧情推演缓存

**场景**：同一上下文多次推演不同方案

```python
# 剧情推演
context = "主角张三刚突破筑基期，遇到黑衣人追杀..."
outline = "第一章：少年出茅庐..."

# 第一次推演（3模型对比）
plan_glm = call_llm(model="glm", context=context, outline=outline)
plan_deepseek = call_llm(model="deepseek", context=context, outline=outline)
plan_qwen = call_llm(model="qwen", context=context, outline=outline)

# 缓存推演结果
cache.set(f"plot_{hash(context)}_{hash(outline)}", {
    "glm": plan_glm,
    "deepseek": plan_deepseek,
    "qwen": plan_qwen,
}, expire=86400)  # 缓存24小时

# 后续选择方案时，直接读缓存
selected_plan = cache.get(f"plot_{hash(context)}_{hash(outline)}")["qwen"]
```

**收益**：避免重复推演，快速切换方案

### 3.3 去AI味检测缓存

**场景**：同一章节多次检测

```python
# 检测文本
text = "主角望着远方的烈焰谷，眼中闪过一丝决然..."

# 第一次检测
score_v1 = call_llm(model="humanizer", text=text)

# 修改后再次检测
text_modified = "张三望着远方，眼神坚定..."
score_v2 = call_llm(model="humanizer", text=text_modified)

# 如果改回去，读缓存
if text_modified == text:
    score_v1 = cache.get(f"humanizer_{hash(text)}")
```

**收益**：避免重复检测，加速迭代

### 3.4 知识库检索缓存

**场景**：相似查询快速返回

```python
# RAG检索
query = "主角突破境界的描写技巧"

# 第一次检索
results = rag.search(query, top_k=5)
cache.set(f"rag_{hash(query)}", results, expire=3600)

# 相似查询（允许模糊匹配）
similar_query = "突破境界怎么写"
cached_results = cache.get_similar(f"rag_", similar_query)
```

**收益**：相似问题秒级响应

## 四、缓存策略设计

### 4.1 缓存键设计

```python
# 格式：{类型}_{内容哈希}_{参数哈希}
cache_keys = {
    "prompt_abc123": "提示词缓存",
    "plot_def456": "剧情推演缓存",
    "humanizer_ghi789": "去AI味检测缓存",
    "rag_jkl012": "RAG检索缓存",
    "fact_mno345": "事实快照缓存",
}
```

### 4.2 过期策略

| 类型 | 过期时间 | 原因 |
|------|---------|------|
| 提示词 | 1小时 | 提示词不变 |
| 推演结果 | 24小时 | 方案可能调整 |
| 检测结果 | 10分钟 | 文本可能修改 |
| 检索结果 | 1小时 | 知识库可能更新 |
| 事实快照 | 永久 | 事实不变 |

### 4.3 淘汰策略

- **LRU**（Least Recently Used）：优先淘汰最久未使用的缓存
- **LFU**（Least Frequently Used）：优先淘汰使用频率最低的缓存
- **TTL**（Time To Live）：超过时间自动淘汰

## 七、风险提示

| 风险 | 说明 | 应对措施 |
|------|------|---------|
| 缓存过期 | 数据可能过时 | 设置合理TTL，关键数据强制刷新 |
| 缓存穿透 | 不存在的数据反复查询 | 缓存空值，设置短TTL |
| 缓存雪崩 | 大量缓存同时过期 | 过期时间加随机值，分散压力 |
| 缓存一致性 | 源数据变更但缓存未更新 | 主动失效机制，写操作清空相关缓存 |
