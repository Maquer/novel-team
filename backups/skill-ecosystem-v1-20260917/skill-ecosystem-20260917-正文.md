## 正文

我翻到一个 1920 星的 Skill 仓库。作者三个月提交 21 次，没有 CI，没有测试，没有度量脚本。README 写满"实测"数据，但全是散文引用，你没法复现。

同一时间，另一个 5 星的仓库 SkillForge 公开了编辑预算、+5pp 硬门槛、14 类边界测试。每次改 Skill 必须在没见过的题上严格改进，否则不接受。

**星数和质量没有直接关系。** 评估一个 Skill 好不好，靠的不是 GitHub 右上角那个数字。

### 星数高的 Skill 为什么更危险

有人会反驳：星数高说明用的人多，用的人多说明有用。

这个逻辑在 npm 时代成立，在 Skill 生态里不成立。原因很简单——Skill 安装成本太低。`npx skills add` 一行命令，73 个 AI 编程工具通用。

装一个 Skill 比装一个 npm 包还快。低门槛意味着安装数反映的是"听说"而不是"验证过"。

更危险的是，加载 Skill 可能让模型变差。Nick Nisi 在 WorkOS 公开过一个案例：同一个任务，不加载 Skill 时模型准确率 97%，加载后跌到 77%。Philipp Schmid 在 Google DeepMind 给出过另一个方向的数据：把 10000 行自动生成的 Skill 砍到 553 行手写规则，准确率反而提升，运行时间从 68 分钟降到 6 分钟。

**加载 Skill 不是免费午餐，它可能主动伤害模型。**

星数高不代表这个 Skill 经过了验证。Vercel Skills 生态里安装量最高的 Skill 达到 15.19 万次，但这个数字只说明"被装过"，不说明"被验证过有效"。有人列过一份"6 个最火的 AI 思维 Skill"清单，点进去全是 404——营销号编的，根本不存在。

Skill 生态的星数和安装数，更像传播力指标，不是质量指标。

### 好 Skill 的 4 个硬指标

既然星数靠不住，那看什么？我翻完 200 多个 Skill 仓库的归档笔记，发现能通过的都满足四个硬指标。不是每个全占，但至少占两个以上。

**指标一：有硬门槛，不是"看起来好就行"**

微软的 SkillOpt（16894★，2026-09-17 数据；arXiv:2605.23904）把这套做到了极致。每次改 Skill 文档，必须在 held-out 数据集上严格改进才接受。

候选分数必须大于当前分数，大于历史最好分数，否则直接拒。它自设了一个 +5pp 门槛——提升不到 5 个百分点，不算有效改进。

翻译成大白话：改了 Skill 之后必须在没见过的题上考一遍，考不过就回滚。held-out 就是没让模型见过的题——你训的时候用一批题，考的时候用另一批题，防止 Skill 只是记住了训练题。这套机制叫"验证门控"。

**指标二：有可复现度量，不是"我说好就好"**

SkillForge（cslsolow，学术论文）做了一个更狠的设计——专门的泄漏过滤器。它从 Agent 修复 Bug 的轨迹里蒸馏 Skill，但蒸馏完必须过滤掉可能泄漏评测数据的部分。你拿到的 Skill 是干净的，不会被评测集污染。

对比之下，前面那个 1920 星的 writing-dna-skill，README 写"300 篇样本、117.9 万字、5 个模型实测"，但度量脚本不随仓库发布。你没法复现那个"实测"。**"实测过"和"可复现"是两件事。**

**指标三：有反滥用边界，不是"什么场景都能用"**

浙大和北大联合开源的 Easel（406★）给每个 Skill 加了 argparse 漂移校验——解析 Skill 文档里写的命令参数，对照脚本实际支持的参数，抓"文档和代码不一致"。它还有 200 行上限和三层加载机制，防止 Skill 膨胀。

**指标四：有反证机制，不是"只有成功没有失败"**

cc-thinking-skills（1310★）公开了一份 AUDIT.md，28 个 Skill 全部判"人工隔离"——数据不支持自动留存。唯一正向数据 +4.0pp，低于自设的 +5pp 门槛，判"方向对但不达标"。

它甚至锁定了 14 个被误删 artifacts 的 SHA-256，禁止它们再被当证据。锁定 SHA-256 意味着即使 artifacts 被误删，你也能从历史记录里确认它曾经存在、内容是什么——禁止用美化过的版本当证据。

这四个项目各自占了不同的指标——没有一个是四个全占的。这也说明，好 Skill 是组合条件，不是单一卖点。

**好 Skill 不是没有失败，是失败被记录、被锁定、被禁止美化。**

### 那 Skill 到底该不该装

看完四个指标，可能有人想卸载所有 Skill。别急。

Skill 生态里有认真做事的团队。Easel 的 112 个 Skill 覆盖了从选题发现到发布归因的五层闭环，六平台真实发布，画像驱动跨会话进化。

Vercel Skills 的生态基础设施（30622★，138 贡献者）让 73+ 个 Agent 共享同一份 Skill，版本管理和私仓认证都做了。skills.sh 排行榜按安装数排序，单 Skill 最高 15.19 万次安装——但安装数只反映传播力，不反映验证深度。

关键不在"装不装"，在"装之前过不过四个指标"。SkillOpt 的部署产物只带一份静态 Markdown，零额外推理时模型调用——训练时的重活全离线，部署时没有负担。

Philipp Schmid 的案例也证明：把 10000 行砍到 553 行手写，准确率提升、运行时间下降。**精简的 Skill 比膨胀的 Skill 更有效。**

答案：装，但只装通过硬门槛、可复现度量、反滥用边界、反证机制这四道关的。通不过的，星数再高也别碰。

### 这套清单什么时候不该用

四个指标有边界。

SkillOpt 的整套训练循环依赖"冻结模型"这个前提——模型权重不变，只改 Skill 文档。你在 9 月训出来的 Skill，到 10 月模型升级后可能就不灵了。如果你的底层模型每周都在更新，held-out 数据集的参考价值会快速衰减，验证门控也会跟着失真。

writing-dna-skill 的作者自己承认，某些规则"只对少数模型成立"，模型更新后规则会过期，但仓库没有更新机制。**评估清单本身也会过期。**

这套方法适用于"Skill 声称能做事、需要验证是否真做到了"的场景。如果某个 Skill 只是娱乐性质、没有量化目标，套这四个指标是过度审查。

### 结尾

在评论区聊一聊——你最近装过的 Skill 里，有几个通过了这四道关？
