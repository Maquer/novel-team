## 一、工具概述

### 1.1 基本信息

| 项目 | 内容 |
|------|------|
| 名称 | ai-novel-writer |
| 定位 | AI小说创作系统 v6 · **世界模拟** |
| 核心创新 | **不预设大纲**，让世界按自己的逻辑往前跑 |
| Stars | 5 ⭐ |
| License | MIT |
| 依赖 | 零第三方依赖（仅标准库：sqlite3/http.server/urllib/json/argparse）|

### 1.2 为什么重写？

> 大纲驱动的文本有稳定的**结构指纹**，检测器一眼能认出来：
> 1. 情节因果过于工整
> 2. 每章自闭环
> 3. 结尾靠"主角想通了"收束
> 4. 主题被叙述者直接讲出
> 5. 时间永远线性
>
> **病根在结构里，表面润色救不回来。**
>
> 世界模拟天然破解这五条：多角色并行让因果必然杂乱；世界状态连续让章节无法自闭环；章节以**世界事件**收尾而不是内心顿悟；推演只问"发生了什么"从不问"这意味着什么"；蒙太奇与多线并行天然打破线性。

## 二、架构设计

### 2.1 五层架构

```
交互层          Web 创作台（五视图） / CLI
   ↓
决策调度层 ★   什么时候停下来问人（三托管模式 × 四触发类型）
   ↓
世界引擎       推演：状态+目标 → 结构化事件流（四道一致性防线）
   ↓
角色代理层     每个角色按自己的性格与目标做决定
   ↓
内容生成层     把事件流写成文学正文
   ↑
数据层         40 表 / 3 视图 / 3 触发器（贯穿全部层级）
```

### 2.2 数据库设计（40表/3视图/3触发器）

| 分组 | 表 |
|------|------|
| 世界 | `novels` `world_settings` `world_state` `world_entities` `world_rules` `world_clock` `timeline` |
| 角色 | `characters` `character_goals` `character_relations` `character_knowledge` |
| 事件 | `events` `event_seeds` `story_nodes` `branches` |
| 事实 | `facts` `fact_candidates` `fact_conflicts` `fact_sources` |
| 地点 | `location_history` `location_beliefs` |
| 线索 | `foreshadowing` |
| 决策 | `decision_points` |
| 章节 | `chapters` `chapter_versions` `chapter_event_links` |
| 配置 | `app_config` `providers` `model_presets` |

### 2.3 核心流程

```
初始化世界 → 推演事件流 → 岔路决策 → 写成正文 → 发布=确认进世界
```

## 三、核心创新

### 3.1 世界模拟（World Simulation）

**不预设大纲**，而是：
1. 初始化世界背景 + 核心张力 + 世界状态量 + 角色
2. 让角色按自己的性格和目标行动
3. 产生结构化事件流（谁/做了什么/为什么/结果）
4. 到关键岔路停下来问用户
5. 把发生的事写成正文

### 3.2 四道一致性防线

| 防线 | 位置 | 管什么 |
|------|------|--------|
| ① 状态约束 | 推演前 | 把已确定的事实喂给模型，防止凭空改变 |
| ② 因果校验 | 推演后 | 检查事件是否依赖了不存在的前提 |
| ③ hidden tracker | 推演中 | 性格变化缓慢积累，达到阈值才跃迁 — **防角色突变** |
| ④ 用户否决权 | 推演后 | "这条不算"的最终手段 |

### 3.3 决策调度层

**三托管模式**：
| 模式 | 谁决定 |
|------|--------|
| `viewer` | 全 AI，用户只看 |
| `director` | 主角归用户，其余 AI（**默认**）|
| `tabletop` | 全部用户定 |

**四触发类型**：
| 类型 | 说明 |
|------|------|
| `moral` | 道德两难 |
| `cost` | 重大代价 |
| `irreversible` | 不可逆行动 |
| `user_focus` | 用户关注的焦点 |

### 3.4 正文回流（最重要的语义）

> **点「发布」不是改一个状态字段，而是作者在确认"这一章写下的内容成立"。**

发布触发正文回流：
```
抽取（这一章实际写了什么）
  → 折成 projection
  → 分类（认知 / 候选 / 世界）
  → 三分流落库
  → 与正史冲突比对
  → 无 error 才 apply_soft_projection
```

**两条必须守住的边界**：
1. 只有 `severity="error"` 的冲突才拦
2. 待选事件不许被顺手带进世界

### 3.5 七级模型档位

| 档位 | 用途 | 建议 |
|------|------|------|
| `world_sim` | 世界推演 | 中档（**成本命门，高频**）|
| `character_decide` | 角色决策 | 中档 |
| `option_gen` | 选项生成 | 强模型 |
| `prose_gen` | 正文生成 | 强模型 |
| `state_extract` | 状态抽取 | 中/小模型 |
| `completion_judge` | 完结判定 | 强模型 |
| `summarize` | 摘要 | 小模型 |

### 3.6 认知分级

```python
# 角色知道什么、以为什么、听说什么，分四层存放
know      # 确知事实
believe   # 相信（可能错）
suspect   # 怀疑
infer     # 推断
```

**判据**：不给这段，模型会让毫不知情的人径直走向秘密地点找人，信息不对称当场破功。

## 六、关键发现

### 6.1 核心哲学

> **规则越密，越容易被跳过或走形式。**
> **大纲驱动 = 结构指纹 = AI味。**
> **世界模拟 = 因果杂乱 = 去指纹。**

### 6.2 正文回流的语义

这是本项目最深刻的设计：
- 发布 ≠ 改状态字段
- 发布 = 作者确认"这一章写下的内容成立"
- 触发正文回流，把正文真正结算进世界

### 6.3 成本优化策略

- 推演用**中档模型**高频跑（成本命门）
- 写作用**强模型**低频跑（体验关键）
- 选项生成用强模型（影响体验）
- 摘要用**小模型**（节省成本）

### 6.4 认知分级的重要性

> 角色的行动依据是**认知**不是事实。
> 不给"他知道什么"这段，模型会让他们全知全能。

## 七、结论与建议

### 7.1 核心价值

ai-novel-writer v6是一个**完全不同的创作范式**：从"大纲驱动"转向"世界模拟驱动"。它认为：
- 大纲驱动的结构是AI味的根源
- 世界模拟能让因果自然杂乱
- 用户只需在关键岔路做决定

### 7.2 与小说团队的关系

| 维度 | 评估 |
|------|------|
| **可运行** | ✅ Python CLI，iSH完全可行 |
| **可借鉴** | ✅ 高度可借鉴（世界模拟+防线+认知分级）|
| **可复用** | ✅ 部分可复用（核心逻辑可移植）|

### 7.3 推荐集成路径

1. **短期**：借鉴四道防线+认知分级
2. **中期**：开发世界模拟引擎CLI版
3. **长期**：评估是否重构SOP为三阶段
